## User story

As a player, I want a Twine story shipped as a zip to show its own pictures, fonts and styles, so that it looks as
its author made it instead of showing broken images and stray symbols.

## Background

Found playing *Les lettres du Docteur Jeangille* (`rpis77r72fg8228`, SugarCube). Its IF Archive file is a 2 MB zip,
`DoctorJeangillesLetters.zip`, whose primary is `DoctorJeangillesLetters/index.html`. The reader loads, but shows
symbols in the text, and **the clickable symbols that move the story on are missing**: the game cannot be played
past its first screen.

- The loader keeps only the primary file of a zip (`extractPrimary` in `src/catalog/storyFile.ts`); the other entries
  are dropped.
- The frame's `<base>` is the zip's own URL (`baseUrl={state.game.file.url}` in `PlayScreen.tsx`), so every relative
  reference of the story (`img/…`, `fonts/…`, extra `.css` / `.js`) points to a file that does not exist on the IF
  Archive.
- Most likely result: missing pictures, and an icon or ornament font that never loads, so its characters show as
  boxes or symbols. Not checked against the real zip (the dev sandbox cannot reach the IF Archive); confirm first.

## Scope

- **Keep the zip's other files.** Unzipping a Twine game keeps, besides the primary, the entries under the primary's
  folder (e.g. `DoctorJeangillesLetters/**`) whose type the frame can use: images (`png`, `jpg`, `jpeg`, `gif`,
  `webp`, `svg`), fonts (`woff`, `woff2`, `ttf`, `otf`), `css` and `js`. Audio and video are dropped (sound is ignored,
  as for Glulx). They stay in memory for the session only.
- **Serve them to the story.** References to these files resolve to the zip's data instead of the network:
  - Before the frame loads: in the story's HTML, relative references that name a kept file (attributes `src` / `href`,
    CSS `url(…)` and `@import`, and paths inside the passage text, e.g. SugarCube `[img[…]]` or a passage's `<img>`)
    are rewritten. Paths are matched after normalising `./`, `../` and `%20`, and case-insensitively as a fallback
    (zips built on other systems, like `extractPrimary`). A linked stylesheet's own relative `url(…)`s resolve from the
    stylesheet's folder.
  - `<link rel="stylesheet">` and `<script src>` naming a kept file are inlined (a `<style>` / `<script>` with its
    text), so they load in order and keep working in the opaque-origin frame.
  - At run time, best effort: the frame script resolves elements the story creates later (`img`, `source`, inline
    `style` with `url(…)`) whose relative URL names a kept file.
  - Choose and record the mechanism (`data:` URLs in the HTML, or `blob:` URLs created inside the frame from bytes
    posted by the reader). Fonts must load: a `blob:` URL made in the parent page is cross-origin for the frame.
- **Caching.** A cached story file (< 512 KB, SPEC §5.5) must give the same result on a second session: cache the
  primary plus its kept files (or the zip), not the primary alone. Larger stories are downloaded again in each session,
  as now.
- **Limits.** A cap on the total size of kept files (e.g. 8 MB unpacked) to protect the e-reader's memory; past it,
  keep the files in their order of reference, then drop the rest and say so in the console.
- `<base>` stays for references that are not in the zip (absolute or not found).
- SPEC §4.3 (and §5.5 if caching changes) updated.

## Acceptance criteria

- [x] *Les lettres du Docteur Jeangille* shows its pictures and fonts with no stray symbols, and its links to the next
      passage are there and work (desktop browser and the Kindle), or the Notes say what it still lacks and why.
      _Desktop browsers and the owner's Kindle: checked (see Notes)._
- [x] A zipped Twine fixture with a picture, a font, a linked stylesheet (with a `url(…)` to a picture) and a linked
      script plays with all of them, from a download and from the cache.
- [x] A zipped Twine story with no other files plays exactly as before.
- [x] The Twine chunk and first-load sizes stay within `size-budget.json`.

## Required tests

**Unit (Vitest)**

- Unzipping keeps the primary's folder and the allowed types only; drops audio / video and files outside the folder;
  applies the size cap.
- Reference rewriting: `src` / `href` / CSS `url()` with quotes, no quotes, `./`, `../`, `%20`, a different case; a
  stylesheet's relative URL resolved from its own folder; absolute URLs, `data:` URLs and references to missing files
  left alone; a passage's `[img[…]]`.
- Cache round-trip of a story with its files.

**E2E (Playwright)**

- The zipped fixture (built at install, like the Twine fixtures, served with `page.route`): the picture is loaded
  (`naturalWidth > 0`), the font is used (`document.fonts.check`), the linked style and script took effect; then
  reload and check again from the cache, with the network blocked.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Audio and video in Twine stories.
- Assets of non-Twine games in zips (Glulx and Z-machine use Blorb; Ink is a single file).
- The e-ink restyling of a story's own colours or filters (a separate small fix: black text inside the story, not only
  on its containers).
- Serving zips through `unbox.ifarchive.org`: its URLs cannot be predicted offline, and fonts from it need CORS.
- Flagging in the catalogue which Twine zips carry assets.

## Notes & decisions

- **Cause confirmed** (a temporary CI job, the IF Archive being out of the dev sandbox's reach): the zip
  (`springthing/2024/DoctorJeangillesLetters.zip`, 24 entries, 3.9 MB unpacked) holds `index.html` (0.7 MB, SugarCube),
  `all.css` (Font Awesome 6, imported by the story's stylesheet with `@import url('all.css')`) and its
  `webfonts/fa-*.woff2|ttf`, nine handwriting fonts in `fonts/*.ttf` (default "Homemade Apple"), three paper textures
  in `images/*.png`, a cover and `info.txt`. The menu's links are Font Awesome icons (`<i class="fa-solid …">`): with
  `all.css` and its fonts missing, they had no glyph and no size, so they could not be seen or tapped. The `☙ ❧ ❦`
  around the links are Unicode fleurons, not icons.
- **Checked on the real game** (the same temporary CI job, playing it through the app from the IF Archive, in
  Chromium and WebKit at e-reader and desktop sizes): Font Awesome, Homemade Apple and Allura load; the four menu icons
  have a size (26–37 × 30 px) and the passage's feather icon too; "Start Reading" leads to the first letter; the menu's
  paper texture is a `data:` URL; no request escapes to the IF Archive and the console is clean. The job was removed
  before merge. **On the owner's Kindle:** the symbols show and the game is playable, despite a page of about
  8.5 MB once SugarCube has copied its stylesheet (the fonts are in it in base64). It looks different from the
  author's design: the e-ink stylesheet replaces its leather and paper backgrounds and handwriting fonts with black
  on white in the reader's font; its icons and pictures stay. It plays in English: the only downloadable file is the
  English version (the French one is only on itch.io), which the catalogue says since S2.6.
- **Mechanism: `data:` URLs in the page**, written before the frame loads, and inlined `<style>` / `<script>` for
  linked stylesheets and scripts. They load in the opaque origin, fonts included, need no message round trip, and work
  the same from the cache. Cost: the page holds the files in base64 (+33 %). To limit it, a font's `src:` keeps only its
  first source found in the zip (Font Awesome lists `woff2` then `ttf`). `blob:` URLs made inside the frame were the
  alternative; they would need the bytes posted before the story's own scripts and styles run.
- **Run time:** the frame script watches, from its start and only for a story with files, `src` attributes and
  `style` attributes with `url(…)`; a relative reference is sent to the reader, which answers with a `data:` URL when
  it names a kept file. Elements already rewritten are left alone (a `data:` URL is not relative).
- **Rewriting** (`src/engines/twine/assets.ts`, pure, tested): `src` / `href` / `poster` attributes (in the markup and
  in the passages' escaped text), `url(…)` with any quotes (written back unquoted, so it can sit in a quoted
  attribute), `@import` (inlined, with the imported file's own folder; a loop or more than 4 levels is dropped),
  `[img[…]]` / `[<img[…]]`. Absolute, root-relative, `#`, `data:` and `blob:` references and files not in the zip are
  left alone.
- **Unzipping** (`extractTwine` in `src/catalog/storyFile.ts`): entries under the primary's folder (the folder of the
  entry found, also when found by name in another case or folder) whose extension is an image, font, `css` or `js`;
  ordered by first reference (the page, then kept styles and scripts, then the rest by path) for the 8 MB cap. Non-
  Twine zips still keep the primary only.
- **Cache:** a story with files is stored as one zip (stored entries `story` and `f/<path>`, then deflated as usual),
  flagged `files: 1` in the record; the 512 KB limit applies to the whole. A SugarCube story (≈ 600 KB of format code)
  is never cached, zipped or not; *Les lettres du Docteur Jeangille* (0.7 MB page) is downloaded again in each
  session, as before. The fixture is therefore Harlowe (0.47 MB with its files).
- **Fixture:** `tests/fixtures/twine/lamp-files.twee` → `lamp-files.zip`, built at install by
  `scripts/fixtures/build-twine.ts` (picture drawn by the ebook's PNG encoder, font copied from `@fontsource/literata`,
  fixed dates so the zip only changes with its content). The e2e serves it in place of the sample Twine game's file
  with `page.route`, so the sample catalogue does not change.
