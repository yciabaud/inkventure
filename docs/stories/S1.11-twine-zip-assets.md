## User story

As a player, I want a Twine story shipped as a zip to show its own pictures, fonts and styles, so that it looks as
its author made it instead of showing broken images and stray symbols.

## Background

Found playing *Les lettres du Docteur Jeangille* (`rpis77r72fg8228`, SugarCube). Its IF Archive file is a 2 MB zip,
`DoctorJeangillesLetters.zip`, whose primary is `DoctorJeangillesLetters/index.html`. The reader loads, but shows
symbols in the text, and **the clickable symbols that move the story on are missing**: the game cannot be played
past its first screen.

- The loader keeps only the primary file of a zip (`extractPrimary` in `src/catalog/storyFile.ts`); the other entries
  are dropped.
- The frame's `<base>` is the zip's own URL (`baseUrl={state.game.file.url}` in `PlayScreen.tsx`), so every relative
  reference of the story (`img/…`, `fonts/…`, extra `.css` / `.js`) points to a file that does not exist on the IF
  Archive.
- Most likely result: missing pictures, and an icon or ornament font that never loads, so its characters show as
  boxes or symbols. Not checked against the real zip (the dev sandbox cannot reach the IF Archive); confirm first.

## Scope

- **Keep the zip's other files.** Unzipping a Twine game keeps, besides the primary, the entries under the primary's
  folder (e.g. `DoctorJeangillesLetters/**`) whose type the frame can use: images (`png`, `jpg`, `jpeg`, `gif`,
  `webp`, `svg`), fonts (`woff`, `woff2`, `ttf`, `otf`), `css` and `js`. Audio and video are dropped (sound is ignored,
  as for Glulx). They stay in memory for the session only.
- **Serve them to the story.** References to these files resolve to the zip's data instead of the network:
  - Before the frame loads: in the story's HTML, relative references that name a kept file (attributes `src` / `href`,
    CSS `url(…)` and `@import`, and paths inside the passage text, e.g. SugarCube `[img[…]]` or a passage's `<img>`)
    are rewritten. Paths are matched after normalising `./`, `../` and `%20`, and case-insensitively as a fallback
    (zips built on other systems, like `extractPrimary`). A linked stylesheet's own relative `url(…)`s resolve from the
    stylesheet's folder.
  - `<link rel="stylesheet">` and `<script src>` naming a kept file are inlined (a `<style>` / `<script>` with its
    text), so they load in order and keep working in the opaque-origin frame.
  - At run time, best effort: the frame script resolves elements the story creates later (`img`, `source`, inline
    `style` with `url(…)`) whose relative URL names a kept file.
  - Choose and record the mechanism (`data:` URLs in the HTML, or `blob:` URLs created inside the frame from bytes
    posted by the reader). Fonts must load: a `blob:` URL made in the parent page is cross-origin for the frame.
- **Caching.** A cached story file (< 512 KB, SPEC §5.5) must give the same result on a second session: cache the
  primary plus its kept files (or the zip), not the primary alone. Larger stories are downloaded again in each session,
  as now.
- **Limits.** A cap on the total size of kept files (e.g. 8 MB unpacked) to protect the e-reader's memory; past it,
  keep the files in their order of reference, then drop the rest and say so in the console.
- `<base>` stays for references that are not in the zip (absolute or not found).
- SPEC §4.3 (and §5.5 if caching changes) updated.

## Acceptance criteria

- [ ] *Les lettres du Docteur Jeangille* shows its pictures and fonts with no stray symbols, and its links to the next
      passage are there and work (desktop browser and the Kindle), or the Notes say what it still lacks and why.
- [ ] A zipped Twine fixture with a picture, a font, a linked stylesheet (with a `url(…)` to a picture) and a linked
      script plays with all of them, from a download and from the cache.
- [ ] A zipped Twine story with no other files plays exactly as before.
- [ ] The Twine chunk and first-load sizes stay within `size-budget.json`.

## Required tests

**Unit (Vitest)**

- Unzipping keeps the primary's folder and the allowed types only; drops audio / video and files outside the folder;
  applies the size cap.
- Reference rewriting: `src` / `href` / CSS `url()` with quotes, no quotes, `./`, `../`, `%20`, a different case; a
  stylesheet's relative URL resolved from its own folder; absolute URLs, `data:` URLs and references to missing files
  left alone; a passage's `[img[…]]`.
- Cache round-trip of a story with its files.

**E2E (Playwright)**

- The zipped fixture (built at install, like the Twine fixtures, served with `page.route`): the picture is loaded
  (`naturalWidth > 0`), the font is used (`document.fonts.check`), the linked style and script took effect; then
  reload and check again from the cache, with the network blocked.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Audio and video in Twine stories.
- Assets of non-Twine games in zips (Glulx and Z-machine use Blorb; Ink is a single file).
- The e-ink restyling of a story's own colours or filters (a separate small fix: black text inside the story, not only
  on its containers).
- Serving zips through `unbox.ifarchive.org`: its URLs cannot be predicted offline, and fonts from it need CORS.
- Flagging in the catalogue which Twine zips carry assets.
