## User story

As a player, I want tapping Play to download and start the real game so that the whole catalogue is playable.

## Scope

- XHR arraybuffer download with progress page and timeout; zip extraction when the index says so.
- IF Archive CORS **verified on a Kindle in S0.3** (main site and mirror allow it): download directly; keep the
  SPEC §5.5 fallbacks for files hosted elsewhere.
- Small-file cache in storage (LRU); engine selection by format.
- Error page: retry, open on IFDB, report.

## Acceptance criteria

- [x] Play on a sample catalogue entry downloads (mocked in e2e) and starts the right engine; failures show the error page.

## Required tests

**Unit (Vitest)**

- Format → engine mapping, cache policy, zip extraction.

**E2E (Playwright)**

- Mocked file route → game starts; mocked 404 → error page with retry.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Mirroring pipeline beyond what the CORS result requires.

## Notes & decisions

- **Code**: `src/catalog/storyFile.ts` (lazy chunk with the unzip code: `download`, `extractPrimary`, `fetchStory`),
  `src/catalog/storyFileError.ts`, `src/engines/formats.ts` (format → engine, lazy engine loaders, header check),
  `src/storage/files.ts` (cache), `src/screens/reader/PlayScreen.tsx`. `GameReader` now takes the tuid, title,
  language, engine kind and story bytes of any game; the bundled fixture (`#/play/fixture-z`) goes through it too.
- **Flow**: `#/play/<tuid>` loads `games/<tuid>.json` (a 404 says the game left the catalogue, with a link to the
  Library), picks the engine from the catalogue format, then takes the story from the cache or downloads it while the
  engine chunk loads. The chips follow the game's catalogue language (`?lang=` still overrides it).
- **Download**: XHR `arraybuffer`, directly from the file host (IF Archive CORS verified in S0.3; no relay or mirror
  needed, so none was built). **Timeout = 30 s without receiving anything**, not a fixed total time, so a large file on
  slow Wi-Fi is not cut off. The progress page shows KB received (of the total when the host sends
  `Content-Length`) and a plain meter, redrawn in 5 % (or 64 KB) steps to spare e-ink repaints; Cancel goes back
  to the game page and aborts the request.
- **Zip**: the `primary` file the catalogue names is extracted with fflate's `unzipSync`; the same file name in
  another case or folder is accepted when it is unique in the zip.
- **Header check**: the file must look like a story for its engine (Blorb `FORM…IFRS`, Z-machine version byte 1–8,
  Glulx `Glul`), so a web page answered with 200 shows "not a story" instead of an engine crash.
- **Cache**: story files under 512 KB (after unzipping) are stored deflated under `ik:v1:file:<tuid>` with their URL
  (a different URL in the catalogue means a new version: re-downloaded). Written 2 s after the start so deflating does
  not delay the game. LRU via the store; a new `cache` write mode evicts only other cached files and never raises the
  "storage full" warning, so caching a file can never cost a save.
- **Error page**: Try again, Open on IFDB, and **Report a problem** (a new GitHub issue prefilled with the game, its
  file URL and the error). Reasons: network, HTTP status, timeout, not a story file.
- **Formats without an engine yet** (Glulx, Ink, Twine until S1.7–S1.9) show "Not playable yet" with the IFDB link,
  without downloading anything.
- **Immersive**: every `#/play/…` route now renders full screen; the pages before the game starts (loading,
  download, errors) bring the app's top bar themselves.
- **Removed**: the reader placeholder for catalogue games and its strings (`play.emptyTitle`, `play.emptyText`,
  `play.back`, `reader.demo`).
- **Tests**: unit `formats.test.ts` (mapping, available engines, header check), `storyFile.test.ts` (download with a
  fake XHR: progress, HTTP / network errors, stall timeout, abort; zip extraction; cache hit, new URL, unzip, refusal),
  `files.test.ts` (size threshold, round trip, stale URL, LRU eviction, saves never evicted for a file). E2E
  `play.spec.ts`: Play → progress page → game starts, then again from the cache with the network blocked; zipped
  story; 404 → error page (IFDB and report links) → Try again starts the game; not a story; format without engine;
  missing game. `shell.spec.ts` now expects the download error page after Play (no network in tests).
- **Follow-ups**: IndexedDB for larger files on devices where it works (SPEC §6.2); a real-device check of a large
  download's progress events on the Kindle (S7.1).
