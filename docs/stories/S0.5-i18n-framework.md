## User story

As a French-speaking reader, I want the interface in my language so that I feel at home.

## Scope

- Extend the English-only `t(key, params)` from S0.4 (`src/i18n/i18n.ts`, `en.json`, already used by every shell string) with plural forms, locale detection from `navigator.language`, override persisted in prefs via the storage layer from S0.6 (`getPrefs` / `setPrefs(store, { locale })` in `src/storage/`).
- `en.json` and `fr.json` for all shell strings.
- Date/number helpers not relying on `Intl`.
- Preact hook/context to re-render on locale change.

## Acceptance criteria

- [x] Shell displays in FR when the browser language is `fr-*`, EN otherwise.
- [x] Missing key in FR falls back to EN, never shows raw keys.

## Required tests

**Unit (Vitest)**

- Interpolation, plurals (EN/FR rules), fallback.
- **Key parity test:** every key in `en.json` exists in `fr.json` and vice versa.

**E2E (Playwright)**

- With `locale: 'fr-FR'` Playwright context the top bar labels are French.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Settings UI for switching language (S5.1).

## Notes & decisions

- **API** (`src/i18n/i18n.ts`): `t(key, params)` for the current locale, `translate(locale, key, params)`,
  `setLocale` / `getLocale` / `subscribeLocale`, and a `useLocale()` hook. `App` calls `useLocale()`, so a language
  change re-renders the whole tree (components aren't memoised and `t()` reads the current locale).
  `translateFrom(catalogue, fallback, …)` is the pure core, used to test the English fallback.
- **Persistence** (`src/i18n/locale.ts`): `initLocale(store)` runs in `main.tsx` before the first render: saved
  `prefs.locale` if supported, else the first supported browser language (`navigator.languages`, `language`,
  `userLanguage`), else English. `changeLocale(store, locale | undefined)` saves and applies (ready for S5.1).
  `<html lang>` follows the locale. The e2e test hook gained `getLocale` / `changeLocale`.
- **Plurals**: JSON objects `{ "one", "other" }` rather than ICU syntax (no parser to ship); the form is picked by
  the numeric `count` param with CLDR rules (EN one = exactly 1, FR one = 0 ≤ n < 2). SPEC §7 updated.
- **Formatting without `Intl`**: `formatNumber` (EN `1,234.5`, FR `1 234,5` with U+202F), `formatDate`
  (`29 September 2026` / `29 septembre 2026`), `formatRelativeDate` (today / yesterday / n days ago, then the date
  after 30 days — for the Continue hero in S4.2). Numeric params in messages are formatted for the locale.
- **New keys**: `library.count` (for S3.1) and `time.*` (for relative dates).
- **Missing keys** fall back to English; a key missing everywhere renders as an empty string, never the raw key
  (TypeScript already rejects unknown keys at build time).
- **Tests**: catalogue parity (keys, message kind, placeholders, no empty values), interpolation, EN/FR plurals,
  fallback, detection, override precedence and persistence, formatting. E2E: French browser → French shell and
  `lang="fr"`, saved override wins, runtime switch without reload, French labels don't overflow on any screen.
  The S0.6 e2e "a pref persists across reload" now expects the French heading, since the saved locale is applied.
- Both catalogues are bundled (≈ 1.5 KiB gz each); legacy initial JS went from 53.3 to 55.1 KiB gz.
