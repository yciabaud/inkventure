## User story

As the maintainer, I want a polite crawler of the IFDB API so that the catalogue can be rebuilt automatically.

## Scope

- `scripts/catalog/crawl.ts`: paginated `search?json` queries per supported system/format with `downloadable:yes`; ≤ 1 req/s, identifying User-Agent, retries with backoff.
- Incremental mode using a cache of previously fetched records (keyed by tuid + page version).
- `--record` mode saving responses as fixtures; `--offline` mode reading fixtures.
- Raw output `data/raw/*.json` (gitignored or on data branch).

## Notes & decisions

- **Code**: `scripts/catalog/ifdb.ts` (URLs, parsing), `fetcher.ts` (rate limiter, retries, live / recording / offline
  fetchers), `crawler.ts` (paging, candidates, records, cache), `crawl.ts` (CLI, `npm run catalog:crawl`). Usage in
  `scripts/catalog/README.md`.
- **API shapes from IFDB's source**: ifdb.org is blocked from the development environment, so the response formats come
  from IFDB's code (iftechfoundation/ifdb: `www/search`, `www/viewgame-components/viewgame-api.php`) and its API pages.
  Findings: search pages hold 100 rows (`pg`), with no total and **hidden games left out of a page**, so a short page is
  not the last one: paging stops at the first *empty* page. Errors come back as HTTP 200 `{"error": …}`.
- **Queries**: `scripts/catalog/queries.json`, `downloadable:yes system:<inform|zil|dialog|twine|ink>` (`system:` is a
  case-insensitive substring match on the development system). IFDB's `format:` matches human-readable format names
  that are not in its source, so the real file format is decided from each record's download links
  (`format`: `zcode`, `blorb/glulx`…) in S2.2. Sorted by title (`sortby=ttl`) for stable pages.
- **Records fetched here**: the crawler also fetches each candidate's `viewgame?json`, since the "incremental cache
  keyed by tuid + page version" needs the record. S2.2 then resolves playability from `data/raw/games.json` without
  network. The page version is read from the search row's cover link (`coverart?id=…&version=N`); games without cover
  art have none, so their cached record is refreshed after 30 days.
- **Failures**: a listing IFDB no longer serves (`{"error"}` or 4xx) is skipped and reported; 429 / 5xx / network
  errors that persist after 4 retries stop the run instead of silently dropping games.
- **Fixtures are synthetic** (`tests/fixtures/ifdb/`, invented games, TUIDs `fx…`), shaped after the source above.
  **Follow-up**: run `npm run catalog:crawl -- --record --limit 5` from a machine that can reach ifdb.org (or in the
  S2.3 workflow) to check the live format and replace them with real responses; the live crawl has not been run yet.
