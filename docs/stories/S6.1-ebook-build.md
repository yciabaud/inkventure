## User story

As the maintainer, I want the ebook built automatically from Markdown so that it stays in sync with the app.

## Scope

- `ebook/` Markdown sources per locale, metadata, cover, CSS for e-readers.
- Build script: Markdown → EPUB 3 (e.g. pandoc) → AZW3 via Calibre `ebook-convert`; epubcheck validation.
- Template for game cards generated from `featured.json` + catalogue (cover, pitch, length, "Play now" link, QR code as PNG).
- CI job producing ebook artifacts on tag.

## Acceptance criteria

- [x] `npm run ebook` produces valid EN and FR EPUB (epubcheck clean) and AZW3.
- [x] Deep links in cards point to `#/play/<tuid>` on the configured host.

## Notes & decisions

- **Tools:** Pandoc (EPUB 3, `markdown-implicit_figures`, one file per chapter), EPUBCheck with `--failonwarnings`
  (Debian's `epubcheck` is a jar: run with Java, or `EPUBCHECK_JAR`), Calibre `ebook-convert` (`QT_QPA_PLATFORM=offscreen`).
  All three from apt, locally and in CI. Built and checked here with Pandoc 3.1.3, EPUBCheck 4.2.6, Calibre 7.6: both
  books clean, with the sample and with the published catalogue (12 cards each).
- **Sources:** `ebook/config.json` (host, number of cards), `ebook/ebook.css`, `ebook/<locale>/book.json` (metadata and
  card strings), `ebook/<locale>/NN-*.md` chapters with `{{host}}` and a `<!-- cards -->` marker. The chapters are a
  short draft of the SPEC §8 outline; the final prose is S6.2. The book `rights` line ("Free to share") is a
  placeholder until S7.2 picks the licences.
- **Cards** (`scripts/ebook/cards.ts`, pure, tested): the first 12 games of the locale's `featured.json` list (curated
  first); title, cover, "by author · year · length", "Start here" badge, pitch (curated, else the blurb's first
  paragraph shortened to 140 characters), "Play now" link, QR code. Length labels and the badge reuse the app's
  `library.minutes` / `library.hours` / `filters.start` strings and rounding. **Difficulty:** SPEC §8 lists it, but the
  catalogue has none (forgiveness `fg` is reserved, not emitted): the "Start here" badge stands in for it.
- **Deep links:** `<host>/#/play/<tuid>`, host normalised to end with `/` (query and hash dropped);
  default host `https://yciabaud.github.io/inkventure/` until S7.2's domain (one line in `ebook/config.json`, or
  `--host`).
- **QR codes:** `qrcode-generator` (new dev dependency; the same library the probe page vendors), error correction M,
  written as grayscale PNG by a small encoder (`scripts/ebook/png.ts`, `node:zlib`). The unit test decodes the PNG and
  compares it module by module with the QR code of the expected link.
- **Game covers:** IFDB thumbnails (SPEC §5.6) at 300 × 450, fetched at build time with the catalogue's User-Agent and
  cached in `ebook/build/covers/`; no cover, a fetch error or a non-JPEG/PNG/GIF answer → a text placeholder.
  `--offline` skips them. The URL mirrors the app's `thumbnailUrl` (Node cannot import it: extensionless imports);
  a test keeps them equal. The sandbox cannot reach IFDB, so real covers were only exercised through the cache path.
- **Book cover:** rendered from HTML (app fonts, black on white) to a 1600 × 2560 JPEG with Playwright's Chromium:
  Calibre drops an SVG cover from the AZW3, so it must be raster.
- **CI:** `.github/workflows/ebook.yml` builds both books from the published catalogue in the Playwright image and
  uploads them as the `ebooks` artifact, on `v*` tags, on demand, and on pull requests that touch the ebook (so the
  pipeline is checked before a tag). Not part of the main CI gates. First run (PR #50): both books from the
  published catalogue, 12 cards each with their IFDB covers, EPUBCheck clean, AZW3 written.
- **Follow-ups:** publish the books on the site for direct download (S7.2); check the books on a real Kindle (link
  confirmation, QR size, card page breaks) in S7.1's checklist.
