## User story

As a developer, I want to know whether the Kindle can reload a page and read a stored story file with Wi-Fi off, so
that the offline mode ([S5.3](S5.3-offline-mode.md)) is designed on facts.

## Scope

- A standalone ES5 page `public/probe/offline/` (no build dependency, like the device probe). Its Service Worker
  (`sw.js`, scope `/probe/offline/`) caches only the probe itself, so the app is never affected.
- **Service Worker.** Report whether it registers and activates, whether the page is controlled, and the result
  of the key test: with the site unreachable, the page reloads from the worker's cache (`offline.reload`).
- **Cache API.**
  - A real story file from the IF Archive (CORS) is stored while online and read back from the cache offline.
  - Synthetic files of 1, 5 and 20 MB measure what fits and the read and write times.
- **IndexedDB.** The same 1, 5 and 20 MB files, stored as `ArrayBuffer`s.
- **StorageManager.** `estimate()` and `persist()`, when present.
- **Persistence.** Nothing is deleted between runs, so a reload, a browser restart or a device restart shows
  whether the data survived. A run counter is kept in localStorage. "Clear test data" removes the worker, caches,
  database and counters.
- Report as text and QR codes. The QR codes need no network, so the report can be sent from the offline run.
- Run instructions in [device-reports/README.md](../device-reports/README.md).

## Acceptance criteria

- [x] The probe runs and reports in Chromium; with the site unreachable, the page reloads from its Service Worker
      and finds the story file and test files it stored.
- [ ] A Kindle report (online run, offline reload, after a browser restart) recorded in `docs/device-reports/`, and
      SPEC §2.2, §6.2 and §13 #11 and [S5.3](S5.3-offline-mode.md) updated with what it shows.

## Notes & decisions

- **Why a separate page:** it isolates the Service Worker from the app. A worker registered at the site root would
  intercept the app's requests before the offline mode is designed.
- **E2E:** `context.setOffline(true)` does not reach a Service Worker's own fetches in Chromium, so the test also
  fails every request to the site (`context.route(...).abort()`). Only the worker's cache can then serve the page.
  The offline test runs in Chromium only.
- `check:es5` now checks `dist/probe/**/*.js` (it was `dist/probe/*.js`), so the new folder is covered.
