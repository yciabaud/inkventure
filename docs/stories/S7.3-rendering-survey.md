## User story

As the owner, I want a report of the parser games whose display the reader may get wrong, made by playing them
headless, so that rendering problems are found and fixed before players meet them on the Kindle.

## Background

Raised by the owner on 2026-10-03, after S1.22. The [2026-10-01 comparison](../reports/rendering-2026-10-01/README.md)
looked at the opening and a few turns of the 32 featured games; the problems found since (Bronze's and Lost Pig's
HELP menus) were further in. A read of the GlkOte bridge (`src/engines/glkote-bridge/bridge.ts`) shows what the reader
drops today, each a likely source of new problems:

1. **Styles in the upper window**: grid rows keep their text only, so a menu that marks its selection in reverse video
   (not with `>`) or a map that uses it loses that.
2. **Several windows of a kind**: every grid window writes to the one status, and every buffer window goes into the
   main text (side panels of Glulx games: inventory, hints).
3. **Graphics windows** (Glulx): not shown; only pictures in the text are.
4. **No optional Glk features declared** (`support: []`): no timers, hyperlinks or sound. A game relying on a timer may
   hang or skip a scene.
5. **Characters missing from the e-reader's fonts** (box drawing, arrows, symbols in maps).
6. **Fixed-width text** (ASCII maps, tables) laid out for 80 columns, which wraps on a 600 px screen.
7. **Inform 7 menus** (Basic Help Menus, Menus by Emily Short), whose layout may differ from the Inform 6 library's
   that S1.16 and S1.22 recognise.

## Scope

- A script (`scripts/survey/`, run by hand with `npm run survey:rendering`, never in CI: it downloads story files from
  the IF Archive) that plays, headless, the featured games and the N most-played parser games of the catalogue (N an
  option, 50 by default) with the app's own engines (ZVM, Quixe) and bridge:
  - the intro (any key), then `look`, `inventory`, `help`, `about`, `verbose`, a few keys in any menu (N, Return, a key,
    Q), with a turn limit and a time limit per game;
  - an instrumented bridge records what the game uses that the reader drops or changes: number and types of windows,
    styles in grid windows (reverse video), graphics windows, timer / hyperlink / sound requests, characters outside
    the bundled fonts' coverage, fixed-width lines longer than the reader shows, upper-window screens (S1.22), menus
    the key chips do not name, a command answered with no text, errors.
- A report `docs/reports/rendering-survey-<date>.md`: a table of games × findings (with the turn where each shows),
  then the findings ranked by number of games, each with a proposed fix or story. The raw results (JSON) are not
  committed.
- New stories for the findings that hurt play, added to the backlog with the owner.

## Acceptance criteria

- [x] `npm run survey:rendering` plays the featured games and the top N, and writes the report; a game that fails to
      load or hangs is reported, never stops the run.
- [x] Each of the 7 risks above is detected when present (unit tests on recorded bridge updates).
- [x] The first report is committed, with the follow-up stories proposed.

## Required tests

**Unit (Vitest)**

- The detectors, on recorded GlkOte updates: reverse video in a grid row, two grid windows, a graphics window, a timer
  request, a character outside the fonts, a too-wide fixed-width line, an upper-window menu.
- The report table from fake results.

No e2e test: the script does not touch the app's UI. Plus the global gates: lint, `es-check es5` on the legacy bundle
(unchanged), size budgets (unchanged), CI green.

## Out of scope

- Fixing what the survey finds (follow-up stories).
- Twine and ink games (the 2026-10-01 comparison covered their opening; they have no Glk windows).
- Running the survey in CI.

## Notes & decisions

- **First report:** [rendering-survey-2026-10-03.md](../reports/rendering-survey-2026-10-03.md), 60 parser games (the
  10 featured parser games and the 50 most-rated), all played. The one finding that hurts play: **quote boxes and title
  cards in the upper window** (7 games), cut to 3 rows; proposed as S1.23. The others touch 1–3 games each and are
  noted in the report without a story. No engine error, hang, timer or second window of a kind was found.
- **How it runs:** `scripts/survey/rendering.ts` (Node, run by hand) takes the catalogue from the `catalog` branch (or
  `--catalog DIR`) and the featured list from `content/featured.json`, downloads the story files (1 request per second,
  cached in `data/cache/survey/`, git-ignored, like the raw results in `data/survey/`), and plays each game with
  `scripts/survey/play.ts`. That module and the app's engines are bundled by **esbuild** with the same vendor patches as
  the app's build (`scripts/build/vendor-patches.ts`): Vite's SSR loader does not convert ifvms's CommonJS modules.
- **Script per game:** the intro (any key until a line prompt), then `look`, `inventory`, `help`, `about`, `verbose`,
  `x me`; a menu or key prompt is browsed with `n`, Return, space, `q`… then Escape, back to a line prompt. 60 s per
  game, 15 s per step.
- **Detectors** (`scripts/survey/detect.ts`, on the recorded GlkOte updates): several windows of a kind, graphics
  windows and drawing, timers, hyperlinks (in the text, the upper window or as input), rows of a grid window in
  different styles ("preformatted" counts as "normal" there: a grid is fixed-width anyway), characters outside the
  latin subset of the bundled fonts (the ranges are checked against @fontsource's CSS in a test), and fixed-width lines
  longer than 40 characters **laid out in columns** (a gap of 3+ spaces, or a third of symbols): prose printed in a
  fixed font wraps harmlessly and is not counted. The player adds what the reader does at each prompt: an upper-window
  menu shown in the text area (S1.22), a tall upper window that is not (cut to 3 rows), a command answered with
  nothing, errors, hangs.
- **Z-machine reverse video:** ZVM sends reverse video only to Gargoyle's Glk (`garglk_set_reversevideo`, behind a
  gestalt glkote-term says no to), so it never reaches GlkOte. The player reads it from ZVM's `@set_style` per row of
  the upper window; a reverse first row (the status line, a title bar, as in every Inform game) is not counted.
- **Limits:** a few commands per game, so later scenes (maps drawn mid-game, timed scenes) are not seen; a later run
  can widen the script or the selection (`--top`, `--only`).
