## User story

As a reader, I want game text laid out in pages that I turn by tapping so that playing feels like reading an ebook.

## Scope

- `src/reader/paginator`: splits a sequence of output blocks into pages fitting the text area using DOM measurement; splits long paragraphs across pages by line.
- Reader view: text area, page indicator, tap zones (left 30 % prev, right 70 % next), swipe when available. On the
  Kindle, `'ontouchstart' in window` is false although touch and pointer events fire (S0.3): detect swipes from the
  events themselves (pointer events, with touch events as fallback), never by feature-testing `ontouchstart`.
- Re-paginate on resize/orientation/font change, keeping the current reading position.
- Last-page rule: slot where the command bar/choices will live; earlier pages show "Back to the present ›".
- Demo route rendering a long static fixture text.

## Acceptance criteria

- [x] No scrollbars in the text area on any e-reader project viewport.
- [x] Turning pages never skips or duplicates a line (verified on fixture).
- [x] Page turn < 300 ms on desktop throttled 4× CPU in Playwright (proxy).

## Required tests

**Unit (Vitest)**

- Paginator with mocked measurements: page breaks, paragraph splitting, position preservation on re-pagination.

**E2E (Playwright)**

- Tap right/left turns pages; indicator updates; resize keeps position; last page shows the input slot.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

## Notes & decisions

- **Modules** (`src/reader/`): `paginator.ts` (pure: `paginate(metrics, pageHeight)`, `pageIndexOf`, `pageFragments`,
  `ReaderBlock` = `{ kind: 'text' | 'input', text }`), `measure.ts` (DOM measurement), `pageTurner.ts` (page state,
  reading position and input handling, framework-free), `PagedText.tsx` (the view). S1.3 replaces `ReaderBlock` with
  its `OutputBlock` model or maps one onto the other.
- **Measurement**: all blocks are laid out once in a hidden layer with the text column's class and width; the top of
  each word's first character (a `Range` per word, no DOM writes in between, so a single layout) tells where lines
  start. A page break inside a paragraph is therefore always at a word start, and the continuation, rendered as its
  own `<p>`, wraps exactly like the original (greedy line breaking). Hyphenation is off in the reader for that reason
  (`hyphens: manual`). Without `Range` geometry a block is kept whole.
- **Reading position** = start of the page the reader last turned to. Re-pagination goes to the page containing it
  and does *not* move it, so rotating and rotating back returns to the very same page.
- **Constant text area**: the slot under the text has the same height on every page (the input slot on the last page,
  "Back to the present ›" on the others), so every page has the same height and the paginator needs no special case.
  S1.4 may need a taller slot for chips + command bar; the "Back to the present" bar then keeps that height.
- **Input**: taps use `click` coordinates on the text area (left 30 % back, right 70 % forward); swipes (≥ 40 px,
  mostly horizontal) are read from `pointerdown/up` **and** `touchstart/end` — whichever arrives first handles the
  gesture, and the click that follows a swipe is ignored. These listeners are attached with `addEventListener`, not
  Preact props: Preact picks the event name casing by testing `'on' + name in element`, which is false for touch
  events on the Kindle. Arrow keys / PageUp / PageDown turn pages too (desktop, accessibility).
- **Re-pagination triggers**: window `resize` / `orientationchange`, a `ResizeObserver` on the text area when
  available (top bar, notices, later the keyboard) and web font loads: after each layout the fonts the text is set in are requested with `document.fonts.check()` /
  `load()` and the text is laid out again when they arrive. FontFaceSet events alone failed on WebKit in CI (`ready`
  resolved before the download started, no `loadingdone` in time), leaving the first page laid out in the fallback
  font; an e2e test reproduces that by delaying the fonts and silencing those events. Layouts are skipped when the
  area size is unchanged, except for new text or fonts.
- **Fonts before the first layout**: the first layout waits (up to `FONT_WAIT_MS` = 2 s, "Loading…" meanwhile) for the
  reading fonts, so an e-ink screen draws the page once instead of fallback font then Literata (an extra refresh and
  ghosting). Past the delay the fallback font is used and the text is laid out again when the fonts arrive. Bundled
  fonts are kept (SPEC §3.2: consistent rendering across devices, the Kindle's own fonts are Amazon's, the
  dyslexia-friendly option needs bundling anyway); system fonts were considered and left as an option for S1.2.
- **Reader chrome**: `#/play/demo` is full screen (`isImmersive()`); the app top bar is hidden and drawn over the text
  when the top zone is tapped (no re-pagination); a tap on the page then only closes it. The top zone becomes the
  status line / reader menu in S1.6. Other `#/play/:tuid` routes keep the placeholder (with a link to the demo) until
  S1.3.
- **Demo text**: `src/reader/demo/demoStory.ts`, original text written for the project, lazy-loaded (≈ 4 KiB gz chunk),
  with a paragraph longer than a small page.
- **Tests**: unit (`paginator.test.ts`, mocked metrics): breaks, paragraph splitting, no skip/duplicate over many
  sizes, page height respected, fractional heights, oversized lines, position preservation. E2E (`reader.spec.ts`):
  tap zones + indicator, swipe (mouse drag) and keys, every page walked to check nothing is clipped or scrollable and
  that the fragments rebuild the fixture exactly, last-page slot and "Back to the present", rotate and back keeps
  the position, top bar toggle, tap targets, and page-turn time with the CPU throttled 4× (Chromium only, via CDP;
  6–19 ms measured locally).
- **Follow-ups**: S1.2 could add a "device font" typeface (system serif, nothing to download); `text-align: justify` (S1.2) leaves the last line of a split paragraph unjustified on the first page
  (`text-align-last` on that fragment would fix it); long transcripts will need incremental measurement (only new
  blocks) when S1.3 appends output.
