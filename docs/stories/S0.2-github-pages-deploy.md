## User story

As the project owner, I want every merge to main deployed to GitHub Pages so that I can test the app on a real e-reader.

## Scope

- Workflow building and deploying `dist/` to GitHub Pages on push to main.
- Correct `base` path configuration for Pages (project site) and hash routing assumption.
- Build info (commit SHA, date) exposed in a `version.json` and in the page `<meta>`.

## Acceptance criteria

- [x] After merge, the site is reachable at the Pages URL and loads the legacy bundle on an old browser. _(site confirmed live by the owner; legacy bundle on a real Kindle is covered by S0.3)_
- [x] `version.json` matches the deployed commit. _(deploy run built `258441f`, the merge commit of PR #7)_

## Notes & decisions

- **First deployment**: after the one-time Pages setup (Settings → Pages → Source: GitHub Actions), the merge of PR #7
  (`258441f`) triggered CI on `main`, then the "Deploy to GitHub Pages" workflow, which succeeded; the owner
  confirmed https://yciabaud.github.io/inkventure/ is live. (The cloud dev environment cannot reach github.io, so
  the live `version.json` was not fetched from there.)
- **Workflow** (`.github/workflows/deploy.yml`): triggered by `workflow_run` when **CI** completes successfully for a
  *push* on `main` (so nothing is published unless lint, unit, build, es5, size and e2e passed), plus
  `workflow_dispatch`. It checks out the exact commit CI validated (`workflow_run.head_sha`), rebuilds, re-runs
  `check:es5` and `check:size`, drops `dist/.vite/` (manifest only used by the size check) and deploys with
  `actions/upload-pages-artifact` + `actions/deploy-pages`. Concurrency group `pages`, never cancelling an
  in-flight deployment.
- **Base path**: kept `base: './'` (relative URLs) rather than hard-coding `/inkventure/`: the same build works at
  the Pages sub-path, a custom domain root (S7.2) and in local preview. Hash routing means no 404 fallback page is
  needed.
- **Build info** (`scripts/build/build-info.ts`, a Vite plugin): `dist/version.json` = `{ commit, date }` and
  `<meta name="inkventure-build" content="<commit> <date>">` in every HTML page. Commit from `GITHUB_SHA`, else
  `git rev-parse HEAD`, else `unknown`; date = build time, or `SOURCE_DATE_EPOCH` when set.
- **E2E** (`tests/e2e/deploy.spec.ts`): `version.json` matches the meta tag; and the production build loads and
  navigates from `https://pages.test/inkventure/` (emulated with `page.route`, proxying to `vite preview`, failing on
  any request outside `/inkventure/`). Verified that this test fails when `base` is `'/'`.
- Legacy bundle on an old browser: only `es-check` can be automated; the real check happens on a Kindle with the
  probe page (S0.3), which will print the deployed commit from `version.json`.
