## User story

As a player, I want my game saved automatically and in named slots so that I can stop anytime and come back.

## Scope

- Autosave after each turn (Quetzal via engine) into `ik:v1:save:<tuid>:auto`, compressed.
- On opening `#/play/:tuid`, resume from autosave (with transcript tail restored).
- Save… / Restore… dialogs with up to 5 named slots (name, date, turn).
- Undo: engine undo or previous snapshot (10 in memory).
- Restart with confirmation.
- Progress record (turn count, last played, location) for Home.

## Acceptance criteria

- [x] Reloading the page mid-game resumes at the same turn with the last page of text visible.
- [x] Storage-full while saving shows a clear message and does not corrupt previous saves.

## Notes & decisions

- **State format (deviation from "Quetzal via engine")**: a plain Quetzal file only resumes through the game's own
  `@restore` opcode, not at a pending line input. The Z-machine state is therefore ZVM's autosave snapshot (RAM and
  stacks as a Quetzal file with uncompressed memory, plus the Glk library state), the format Parchment uses to resume
  games, wrapped in a JSON envelope `{format, version, signature}`; a snapshot of another story is refused. ZVM needs
  its Glk dispatch layer for this (`ifvms/src/zvm/dispatch.js`, which also sets an unused `window.GiDispa`).
- **Engine interface**: `restart()` added; `saveState` works between turns only; `restoreState` boots a new VM and swaps
  it in only once it started (a bad save leaves the game running and rejects). `undo()` returns false for ZVM: its own
  undo is driven by the game's UNDO command, so the reader restores its previous turn snapshot (10 in memory,
  `src/reader/undoStack.ts`). The Undo chip in "More…" still sends the game's UNDO command.
- **Autosave**: when the game asks for a command, in a `setTimeout` after the reply is drawn: snapshot for Undo,
  progress record (`turns`, `lastPlayed`, `location`) then autosave with the transcript tail (≈ 8,000 characters /
  80 paragraphs). Resuming, undoing or restoring opens on the page of the last command. The autosave of an ended story
  is kept (the last turn before the end can still be undone or resumed). Restart clears the autosave, keeps the slots.
- **Storage**: `src/storage/saves.ts`, loaded lazily with the engine (it pulls in fflate). Each save is one entry
  (`{v, date, turn, data, text}` + `name` for slots, deflated + base64), so a failed write leaves the previous one intact;
  the Save dialog shows "Storage is full…" and the StorageNotice banner appears too. Autosave failures only show the
  banner.
- **UI**: Save… (disabled unless the game waits for a command), Restore…, Undo (disabled without an earlier turn) and
  Restart in the reader menu. The Save dialog proposes the location as the name and stays open to show the outcome.
- **Follow-ups**: route the game's typed SAVE / RESTORE / RESTART commands to these dialogs (they are cancelled today);
  the turn counter counts commands sent, which may differ from the game's "Moves" (e.g. after the game's own UNDO).
