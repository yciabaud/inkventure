## User story

As a player, I want every game the Library offers to open, so that I never pick one that fails to download or start.

## Background

The [story-file scan of 2026-10-04](../reports/story-file-scan-2026-10-04.md) (S7.4) read the catalogue's 2,104 parser
games the way the app opens them (`extractPrimary`: the file of that name in the zip, whatever its folder). **47 do not
open**:

- 31: the file IFDB names is not in the zip: a different case (`PLAQUE.Z5` / `plaque.z5`, `Broken.z5` /
  `BROKEN.Z5`), a typo or a truncated name (`boinspeed.z5` / `boingspeed.z5`, the Fingertips games), a different folder
  name, or a compilation zip that holds many games;
- 10: the download is not a story file (a web page, a compilation zip with no file named);
- 5: the link is broken (HTTP 404, 403); 1: the zip is damaged.

And **8 Z-machine version 6 games** are listed (Zork Zero, Arthur, Journey, Shogun…): the app does not play version 6
(ZVM plays versions 3, 4, 5 and 8).

## Scope

- **The app:** the file named in the zip is found whatever its case (`extractPrimary`), which opens the case
  mismatches at once.
- **The pipeline** (`scripts/catalog/`, a check like the CORS, ink and pictures checks, cached and at 1 request per
  second): for each game whose file is zipped or not yet checked, download it once and check that it opens — the named
  file is in the zip (case-insensitive), or a single story file of the game's format is; the bytes are a story of that
  format; a Z-machine story is version 3, 4, 5 or 8. Games that fail are left out of the index, and listed in the run's
  summary with the reason (to report to IFDB when it is a typo).
- SPEC §5.2 updated.

## Acceptance criteria

- [x] The 47 games of the scan either open (case fixed, single story file in the zip) or are left out, with their
      reason in the summary.
- [x] Version 6 games are left out.
- [ ] A rerun of `npm run survey:scan` on the new catalogue lists no game it cannot read.

## Required tests

**Unit (Vitest)**

- `extractPrimary`: a different case, a single story file in a zip of several files, none.
- The check: a zip without the file, a page instead of a story, a version 6 story, a good story (recorded fixtures,
  no network).

No e2e test beyond the existing ones (the Library lists what the index holds). Plus the global gates.

## Out of scope

- Fixing IFDB's records (reported by hand from the summary).

## Notes & decisions

- **The app already ignored case.** `extractPrimary` lowercases both names since S1.11 (its tests cover it): the case
  mismatches only failed in the S7.4 scan, whose own copy of the lookup compared names exactly. The scan
  (`scripts/survey/catalog.ts`) now ignores case like the app; the app is unchanged. A zip whose story is under another
  name is fixed by the pipeline instead (below), so the app needs no fallback.
- **Check** (`scripts/catalog/stories.ts`, `check-stories.ts`, `npm run catalog:stories`): every Z-machine and Glulx
  file the resolver may pick (the files of other languages included) is opened once. A zip is downloaded whole (up
  to 64 MB): its story is the file IFDB names, else the only file of that name in another case or folder, else the
  only story of the game's format; that path becomes `archive.primary`. Only the head of a bare file is read (a
  `Range` request for 4 KB, and 72 bytes at a Blorb's executable chunk when it lies further), which keeps the first
  run small (the scan's downloads were 3.4 GB). Z-machine versions 3, 4, 5 and 8 open (ZVM's); versions 1, 2 and 6
  do not. Cache `cache/stories.json` on the `catalog` branch, 180 days; network errors and 5xx are retried at the
  next run and the file is kept meanwhile (never dropped on a network error).
- **Resolver:** a file that does not open is skipped and the next best one used; a game left without any is dropped
  (`story-does-not-open`, detail: the problem and the file). The summary lists the files that do not open with
  their games (to report to IFDB) and the stories found under another name.
- **Glulx games listed as Z-code** (18 in the catalogue: Monk by the Sea, Locked Door X…): IFDB gives the wrong
  format, so the app started ZVM on a Glulx file and failed. Rather than dropping them, the check records the story's
  own format and the resolver uses it: they now open.
- **Zips over 64 MB are left out** (`too-big`, 10 games: big Blorbs with music and pictures, up to 759 MB): an
  e-reader cannot open them, and the weekly run should not download them.
- **Checked offline on the published catalogue** (2,104 parser games, with the files the S7.4 scan downloaded):
  2,049 open (68 of them with the zip's path fixed), 50 are left out (18 story not in the zip, 11 not a story, 10
  zips too big, 10 Z-machine versions 1, 2 or 6, 1 damaged zip), 5 were not downloaded by the scan (the first weekly
  run will check them). Of the scan's 49 "not read": 15 open now, 29 are left out, 5 are those not downloaded.
- **Criterion 3** (a rerun of `npm run survey:scan` on the new catalogue) needs the first weekly catalogue built with
  the check: run the Catalogue workflow by hand after the merge, then the scan.
