## User story

As the curator, I want to maintain the Featured list in a simple file so that the home screen and the ebook highlight great games.

## Scope

- `content/featured.json` schema (tuid, starter flag, pitch per locale).
- Validation script in CI: tuid exists in index, playable, not excluded, pitch present for every UI locale.
- Initial selection of ~10 games (EN + FR) with pitches — proposal to be reviewed by the owner.
- Added with the owner: per UI locale, the best-rated games in that language after the curated ones, so the Home
  shelf can skip the games already in progress (published `catalog/featured.json`).

- [x] CI fails on an invalid entry; initial list validated.

## Notes & decisions

- **Code**: `scripts/catalog/featured.ts` (pure: schema checks, catalogue checks, list building),
  `build-featured.ts` (CLI, `npm run catalog:featured`, `--check` for CI), `check-featured.sh` (CI step),
  `locales.ts` (UI locales from `src/i18n/*.json`; a test checks they match the app's `LOCALES`). SPEC §5.3 updated.
- **Best rated per language** (owner's request): the owner asked to feature the best-rated adventures in the current
  language that are not already in progress. The data side is done here: `catalog/featured.json` has one list per UI
  locale, curated games in that language first, then up to 24 games in that language with at least 3 stars, ranked by
  IFDB's star sort (which weighs the count). Filtering out the games in progress needs the player's progress, so it is
  client side: added to S4.1's scope. With the catalogue of 2026-09-30: EN 8 curated + 24, FR 4 curated + 8 (only
  16 French games, 12 rated).
- **Curated games are shown only in their language's list** (a French game in the FR shelf only), hence the
  validation error for a game whose language is not a UI locale. Every item still needs both pitches: the ebook
  editions may use all of them (S6.2). Follow-up if the owner wants e.g. an English classic on the FR shelf: an
  optional `locales` field per item.
- **Where it is built**: at deployment (`use-published.sh`, deploy and preview) rather than by the weekly catalogue
  run, so a curation change ships with the code. There, a curated game missing from the catalogue is dropped with a
  warning (an IFDB withdrawal must not block deployments); the CI check is strict and makes the next PR red.
- **CI check** reads the `catalog` branch (the real catalogue); without it, only the curated file is checked. The
  unit tests also check `content/featured.json`'s schema and pitches (no catalogue needed).
- **Sample**: `public/catalog/featured.json` comes from `tests/fixtures/featured.json` (two sample games), rebuilt by
  `npm run catalog:sample` and covered by the stale-sample test. Its size is checked with the catalogue files.
- **Initial selection (to review)**: EN — 9:05, Lost Pig, The Impossible Bottle, Violet, Bronze (starters),
  Photopia, Spider and Web, Anchorhead; FR — Le butin du Capitaine Verdeterre (starter), Life On Mars?, Filaments,
  Ombre. Pitches written spoiler-free, ≤ 140 characters.
