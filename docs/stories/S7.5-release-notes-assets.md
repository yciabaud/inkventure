## User story

As the project owner, I want a version tag to give a GitHub release with the ebooks attached and its notes written,
so that releasing V1 (and the next versions) takes a tag and a read, not an afternoon of copying.

## Scope

- The Ebook workflow, on a `v*` tag, attaches the EPUB and AZW3 books to the tag's release (a draft when the tag has
  none), replacing them on a re-run.
- Release notes generated from the repository: catalogue, stories done since the previous tag, latest device
  checklist, first-load sizes, open stories as known issues, books; highlights and extra known issues from an
  optional `docs/releases/<tag>.md`. `npm run release:notes` previews them.
- The notes of v1.0.0 (`docs/releases/v1.0.0.md`).

## Acceptance criteria

- [ ] Pushing the `v1.0.0` tag gives a draft release with the four books attached and notes that need no edit
      beyond a read.
- [x] `npm run release:notes -- --tag v1.0.0` writes the notes locally. _Checked on 2026-10-09 with the published
      catalogue (3,002 games) and the local build's sizes; without ebooks, the Ebooks section says they are not built._

## Out of scope

- Publishing the release automatically: the owner reads the draft and publishes it.
- Running the device checklist: it stays manual (S7.1); the notes copy the latest report.

## Notes & decisions

- **Draft, not published:** a tag pushed with git gets a draft release, so nothing is announced before the owner has
  read it. A release created in GitHub's interface with its tag already has the owner's notes: the job attaches the
  books and leaves notes it did not write alone (it fills them only when empty); the generated ones are in the job
  summary either way.
- **AZW3 attached too,** not only the EPUBs: the download page offers both and the Kindle reads both.
- **The release template (`docs/release-notes-template.md`) is gone,** replaced by the generated notes and
  `docs/releases/README.md`; the device checklist and the launch steps point there.
- **Stories, not pull requests:** the notes list the stories done since the previous tag (the backlog at both tags),
  in a collapsed block grouped by epic; the first release lists them all (56).
- **Sizes:** the release job builds the app with the published catalogue, like Deploy, and reads the first-load rows
  of `check:size --json` (a new option; the table and the gate are unchanged).
- **Date:** the notes' title carries the tag's date (`creatordate`), so a re-run keeps it; a preview before the tag
  exists shows today's.
