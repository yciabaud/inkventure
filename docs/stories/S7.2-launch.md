## Notes & decisions

- **Dependency:** S6.3 was still `in-progress` when this story started (its code was merged; its criteria needed a
  deployment of `main` to check). Started on the owner's request anyway; S6.3 is now `done`.
- **Address: no custom domain for V1.** The site stays at `https://yciabaud.github.io/inkventure/`, already the ebook's
  `host` (`ebook/config.json`), so the books' links point to it with no change. How to move to a custom domain later
  (CNAME, `host`, README, `APP_ORIGIN` in `scripts/catalog/cors.ts`) is in `docs/launch/README.md`; say if you want one.
- **Licence:** `LICENSE`, MIT, "Copyright (c) 2026 Yoann Ciabaud and the Inkventure contributors" (name from the git
  history; `package.json` already said MIT).
- **Third-party licences file: generated, not hand-written.** Vite 7's `build.license` lists the npm packages bundled
  into the app with their licence texts; `scripts/build/licences.ts` (Vite plugin, unit tested) adds what it cannot
  see: Quixe (vendored), core-js and SystemJS (the legacy bundle's polyfills, built separately by plugin-legacy) and
  the probe's QR code script, and writes `dist/licences.txt` (~20 KB, plain text so any browser shows it; not counted
  by any budget). A committed copy would drift at every upgrade. The Twine story formats in `vendor/twine/` only
  build test fixtures and are not served. The e2e `deploy.spec.ts` checks the file lists every component.
- **About:** a last paragraph, "Source code: github.com/yciabaud/inkventure. The licences … in full: <address of
  licences.txt>" (`about.source`, EN/FR), as text like the ebook's address. The Kindle first load went from 195.5 to
  195.7 KiB (budget 200).
- **README:** what the app does, three screenshots reused from the ebook (`ebook/en/images/`, so they stay up to date
  with `npm run ebook:screenshots`), links, credits, licence, and how to run the production smoke test.
- **Production smoke e2e:** `tests/production/smoke.spec.ts` with its own config (`playwright.production.config.ts`,
  `npm run test:production`, so `test:e2e` never touches the network), Chromium and WebKit at 600 × 800, one retry
  (real network). The **Production smoke** workflow (`workflow_dispatch`, optional address input) runs it in the
  Playwright image. It checks `version.json`, the catalogue, `licences.txt`, Home's Featured shelf, the Library, a
  featured Z-machine game downloaded from the IF Archive (fails fast on the error page), and the ebooks: the four
  files of `books.json` with matching sizes, the English EPUB's links to the site and to `#/play/`, the download
  buttons. Checked locally against `vite preview` with the local ebook build (the IF Archive stubbed for the game
  test); it cannot reach the live site from the development container, so its first real run is after merging.
- **Announcement and IFTF:** drafts in `docs/launch/` (English post for intfiction.org, French post for the
  French-speaking community, message to the IFTF describing the crawler, cover thumbnails and downloads), with the
  pre-announcement steps. The owner sends them; the `[…]` placeholders (number of games) are to fill in at launch.
- **Remaining for the acceptance criterion** (owner): merge, let Deploy publish (ebook job green), run Production
  smoke on the live site, then send the IFTF message and the announcements.
- **Closed on 2026-10-02** by the owner. The announcement and the message to IFTF are drafts in `docs/launch/`: sending
  them is up to the owner.
