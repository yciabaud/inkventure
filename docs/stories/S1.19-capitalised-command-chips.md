## User story

As a player on an e-reader, I want to tap the commands a game tells me about ("type GUIDE", "HINT for help"), so
that I don't type them on the virtual keyboard.

## Background

Reported by the owner on 2026-10-02, after S1.12. Games often name their own commands in capitals, and these
commands are not among the command bar's directions and verbs:

- **Repeat the Ending** (`eueqjtej7bvnfp5a`, Glulx): `GUIDE` and other commands written in capitals.
- Common elsewhere: `HELP`, `HINT` / `HINTS`, `ABOUT`, `CREDITS`, `INFO`, `TALK TO`, `THINK`, `RECAP`.

Today the only way to send one is to tap the word in the text: it goes into the field in lower case (`wordAt` +
`insertWord`), and then Enter must be tapped. A multi-word command (`TALK TO`) takes several taps.

## Scope

- While the game waits for a **line**, read the commands the text names in capitals, in the paragraphs since the
  last command (and, on the first turn, the intro):
  - a run of 1–3 words in capitals, each of at least 2 letters (`GUIDE`, `TALK TO`, `X ME`);
  - stronger signal (listed first): the run follows `type`, `try`, `enter`, `say`, `use the command`, `tapez`,
    `essayez`, `la commande`, or is quoted (`"GUIDE"`, `[GUIDE]`).
- **Not commands**: the game title and headings (a paragraph that is entirely in capitals, the `header` / `subheader`
  styles), the room name and the status rows, words in capitals for emphasis inside a sentence with no signal
  (choose and record the rule: e.g. only a run that has a signal, or that the game repeats, or that is a known
  verb), Roman numerals, single letters, and words the command bar already has (`LOOK`, `INVENTORY`, `N`…).
- The chips go in the **verbs row**, before the usual verbs (they push the others into "More…", as narrow screens
  already do). A chip shows the command as written and sends it in lower case. At most 4 such chips; the rest stay
  reachable by tapping the word.
- They go away at the next turn when the new text names none (like the noun chips).
- SPEC §3.6 (Command input) updated.

## Acceptance criteria

- [ ] Repeat the Ending: a `GUIDE` chip when the text names it; a tap sends `guide` and the game answers it.
- [ ] A multi-word command in capitals (`TALK TO …` style, in a fixture) gives one chip that sends the whole
      command.
- [ ] No chip for the title of a game, a heading, a room name or an emphasised word (Lost Pig, Counterfeit Monkey,
      Bronze ordinary turns: verbs row unchanged).
- [ ] Checked on the PR preview and on the Kindle, or the Notes say why not.

## Required tests

**Unit (Vitest)**

- Extraction: `Type GUIDE for a list of commands.`, `[HINT]`, `"ABOUT"`, `TALK TO someone`, French
  (`Tapez AIDE.`), a heading in capitals, an emphasised word (`You are NOT alone.`), a room name, duplicates, the
  4-chip limit, commands the bar already has.

**E2E (Playwright)**

- Extend the Z-machine fixture (`tests/fixtures/zmachine/lamp.inf`, rebuilt and committed): a line in the intro
  naming a command in capitals (e.g. `Type LOGBOOK to read the keeper's log.`); the chip appears, a tap sends it and
  the game answers; the chip is gone after an ordinary turn.

Plus the global gates: lint, `es-check es5` on the legacy bundle, size budgets, CI green.

## Out of scope

- Yes / no and numbered answers ([S1.17](S1.17-contextual-answer-chips.md)).
- Single-key prompts ([S1.12](S1.12-single-key-prompts.md)).
- Commands named in lower case in the prose (too many false positives).
