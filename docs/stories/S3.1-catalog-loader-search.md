## User story

As a reader, I want to search the catalogue by title or author so that I can find a game I have heard of.

## Scope

- Loader for `meta.json` + shards via XHR (ES5), progress page "Loading catalogue…", in-memory cache.
- Library screen: search box, results list (cover as a small IFDB thumbnail, see SPEC §5.6, title, author, year, rating, format, playtime), result count, Pager (10/page small, 15/page large).
- Accent/case-insensitive search on title and author.
- Error state if the catalogue fails to load (retry).

## Acceptance criteria

- [x] Search returns expected games on the sample catalogue; pagination works; state in URL hash.

## Required tests

**Unit (Vitest)**

- Search normalisation, pagination slicing, loader (mocked XHR).

**E2E (Playwright)**

- Type a query, see results, go to page 2, back button restores query and page.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Filters (S3.2).

## Notes & decisions

- **Code**: `src/catalog/loader.ts` (XHR, `meta.json` then the shards one after the other, progress, loaded once per
  session and retried after a failure; refuses another catalogue `version`), `src/catalog/search.ts` (normalisation,
  search, paging), `src/screens/library/LibraryScreen.tsx`. Row and meta types come from `scripts/catalog/emitter.ts`.
- **Search**: runs on submit (Search button or Enter), not on each keystroke, which would redraw the e-ink screen for
  every letter. Every query word must start a word of the title or author; accents are folded with a table (the Kindle
  browser has no `String.prototype.normalize`); Unicode punctuation separates words. Title matches come first.
- **Rows per page are measured** rather than fixed at 10/15: as many 56 px rows as fit between the search bar and the
  pager (8 on a 600 × 800 Kindle, about 5 on a 360 × 740 phone), re-measured after each render and on resize, so a page
  never scrolls. Rows: small IFDB thumbnail (`coverart?…&thumbnail=36x48`, grayscale, initial letter when there is no
  cover or it fails), title, then author, year · ★ rating (count) · play time · format on one line.
- **URL**: `#/library?q=…&page=…`; the back button restores the query (the field is re-created with it) and the page.
  "✕" in the search bar clears the query.
- **Tests**: unit (normalisation, search, paging, loader with a fake XHR). E2E `library.spec.ts` with a 40-game
  synthetic catalogue served by `page.route` (`tests/e2e/helpers/catalog.ts`) and IFDB covers blocked: search, page 2,
  back button, accents, no results, clear, rows fill the page without scrolling, error + retry.
- **Moved**: the "Play the test adventure" link is now on Home (the Library shows the catalogue).
- **Order**: done before S2.4 (Featured) at the owner's request; S2.4 does not block the Library.
- **Pipeline fixes found with the real catalogue** (1,693 games rendered locally from the `catalog` branch): IFDB
  HTML-escapes titles and authors in its JSON (`Lock &amp; Key`, `&quot;…&quot;`), so the resolver now decodes
  entities (`decodeEntities`); titles sort by their words, ignoring leading punctuation (`**COUGH COUGH**`,
  `"Calm…"`). The published catalogue picks this up at its next run (run **Catalogue** after merging to see it now).
- **Grid view** (owner's request, like the Kindle library), the default; "List view" / "Grid view" switches, remembered
  in `prefs.libraryView`. `src/catalog/layout.ts` sizes it from the measured list area: columns of covers at least
  120 px wide, at least two rows (covers shrink on short screens), as many rows as fit (4 × 2 on 600 × 800, 2 × 2 on a
  phone). Each cover has its title under it (two lines at most, `CAPTION_HEIGHT`): the owner noticed that some IFDB
  cover art does not show the title. Covers are the IFDB thumbnail at the tile size (rounded up to 10 px) or the typographic cover (about 63 % of
  the games have no cover art); long author lists on typographic covers are cut to the first author.
- **UI language**: the Kindle browser reports the device language (`en-us` in the S0.3 probe), so an English Kindle
  shows the English UI. A manual choice comes with the Settings screen (S5.1).
