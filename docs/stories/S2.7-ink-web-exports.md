## User story

As a reader who prefers choices to typing, I want the Ink games of IFDB in the Library so that I can play them with the
choice buttons, not only the bundled test story.

## Background

The catalogue has **no Ink game** (3,000 games, 2026-10-01): the resolver keeps an Ink game only when its file is the
compiled story (`.json`, which inkjs plays), and authors almost never publish that. They publish the **web export** of
Inky (*File → Export for web*): an `index.html` with `ink.js`, `main.js` and the story in `story.js`
(`var storyContent = {…};`), often zipped, or the same page on itch.io. IFDB lists those links as `hypertextgame`, so
they are dropped as `unsupported-format`. The compiled story is inside the export, so most of these games could be
played by the existing Ink reader.

## Scope

- **First step: count them.** IFDB and the IF Archive cannot be reached from the dev sandbox: a temporary CI job (as in
  S1.11) lists the crawled games whose development system is ink / inkle, with their links (zip, HTML page, itch.io,
  other host) and, for IF Archive zips, whether they hold a `story.js` with `storyContent`. Record the numbers in the
  Notes before building the rest; drop the story if there are too few.
- **Pipeline.** A link of an ink / inkle game is Ink when it is a compiled `.json`, a zip holding a web export, or an
  HTML page of a web export, on a host the app can read (§5.5, CORS check). The game file records where the story is
  (`archive.primary`: the `story.js` or the `.json` in the zip). Twine detection is unchanged (an HTML page of an ink
  game is not Twine).
- **Loader.** The story's JSON is taken from the file: a `.json` as now; from a web export, the object assigned to
  `storyContent` in `story.js` (or inline in the HTML page). Extracting it must not run the export's scripts. A file
  without a story JSON fails as "Not a story file".
- **Limits.** Exports whose `main.js` adds behaviour the story relies on (external functions, custom tags) may not play
  fully: the reader plays the story with its usual choice buttons and ignores the export's own look.
- Sample catalogue: an Ink game served as a zipped web export (built at install from the Ink fixture, like the Twine
  fixtures).
- SPEC §4.1, §5.2, §5.5 updated.

## Acceptance criteria

- [x] The CI count is recorded in the Notes, with the decision to go on.
- [x] A zipped Inky web export from the catalogue downloads and plays to an ending with taps only, and resumes after a
      reload; the Library's Ink format filter finds the Ink games.
- [x] The Catalogue workflow's summary counts the Ink games kept and the ink games still dropped, by reason.

## Required tests

**Unit (Vitest)**

- Resolver: an ink game's `.json`, zipped web export and HTML page links are Ink; other links of ink games and HTML
  pages of other systems are not.
- Loader: the story JSON from `story.js` (`var` / `let` / `const`, with or without a final `;`), from an inline script,
  from a `.json`; a broken or missing `storyContent` is "Not a story file".

**E2E (Playwright)**

- The sample's zipped Ink export (served with `page.route`) plays a choice, reloads and continues.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- itch.io-hosted games (no CORS, no direct file).
- Running the export's own `main.js` or styles.
- Ink games compiled to other runtimes (Unity, Godot).

## Notes & decisions

- Asked by the owner after the S7.1 Kindle run ("why is there no Ink game?").
- **The count (temporary CI job, 2026-10-01; removed before merge)**: `downloadable:yes system:ink` returns **230
  games** (200 `Ink` / `ink`, 9 inklewriter, 7 Binksi, the rest Godot / Unity builds with ink, blink!). Their links:
  150 on itch.io, 63 zips on the IF Archive (46 hold a compiled story), 16 pages on the IF Archive (`unbox` pages,
  CORS `*`), 58 pages elsewhere (almost none with CORS), 11 inklewriter pages. Per game: **45 have an IF Archive zip
  holding the story** (in a script named after the project, `Arkuwar.js`, `Mech Story.js`…, seldom `story.js`; once
  a compiled `.json` next to a Calico page), **12 an IF Archive page of a web export** (the story in a sibling
  script), 1 a page elsewhere with CORS; 98 are on itch.io only (out of scope). Zips without a story hold a desktop
  build, the `.ink` sources, another zip, or a Binksi page. **Decision: go on** — about 58 games, against none before.
- **Where the story is, found by the pipeline** (`scripts/catalog/ink.ts`, `check-ink.ts`, cache
  `cache/ink.json` on the `catalog` branch, 90 days): IFDB names the export's page (`index.html`), and the story's
  script is named after the project, so neither the resolver nor the loader can guess it. The weekly build opens each
  zip and page once (≤ 1 request/s), follows the page's own scripts (the ink runtime skipped) and records the file
  holding `storyContent`; the resolver points `archive.primary` (zip) or the file URL (page) at it, and drops the
  exports without one (`no-ink-story`) instead of listing games that would fail on Play. For a page outside the IF
  Archive, the CORS check runs on the script (`--ink` on `check-cors.ts`), since that is what the app downloads.
  The same option on `check-pictures.ts` keeps its offline resolution identical to `resolve.ts`.
- **Detection** (`linkFormat`): an ink development system (`\bink(le)?\b`: `ink`, `Ink`, `Godot, Ink`, `Inkle`; not
  inklewriter or Binksi, which are other runtimes) and a zip whose named file is a page or script (or not named:
  then `compressed-no-primary`), or a `hypertextgame` / `.html` link outside itch.io. A compiled `.json` as before.
- **Loader** (`src/catalog/inkStory.ts`, pure): a compiled `.json` (byte order mark skipped) is taken as it is;
  otherwise the object after `var|let|const storyContent =` is cut out by matching braces outside JSON strings and
  parsed with `JSON.parse`; it must carry `inkVersion`. Nothing of the export is evaluated. A file without a story
  is a `format` error ("Not a story file"). The cache keeps the story's JSON only (the export's page, runtime and
  styles are not kept).
- **Sample catalogue**: *Ink and Tide* (`fxinky0000000007`), now with `compressedPrimary: tide/index.html` and an
  itch.io link (left out), resolved with `tests/fixtures/ink-exports.json` (the cache entry `check-ink.ts` would
  write). Its zip, `tests/fixtures/ink/tide.zip`, is built at install by `scripts/fixtures/build-ink-export.ts` from
  `lamp.json`, laid out like Inky's export with the story in `tide.js` and a `main.js` that throws if ever run.
  It is in the sample's featured list (best rated).
- **Summary**: the resolver's job summary has an "Ink games (S2.7)" line (crawled, kept, dropped) and a table of
  the ink games dropped by reason.
- **Follow-ups**: none needed for this story. The ~35 ink games whose only page is on an author's site without CORS
  stay out (`unreadable-host`); itch.io games remain out of scope.
