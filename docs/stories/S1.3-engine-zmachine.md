## User story

As a player, I want to play a Z-machine game in the reader so that the core experience works end-to-end.

## Scope

- `Engine` interface (SPEC §4.2) and `OutputBlock` model.
- GlkOte-compatible bridge translating Glk updates (buffer window, grid/status window, styles) into blocks.
- ZVM integration (from Parchment, licence checked and recorded), lazy-loaded chunk, ES5-safe.
- Bundled freely-licensed fixture Z-game in `tests/fixtures/` and served for the demo; `#/play/fixture-z` route.
- Basic line input field (full command bar is S1.4); char input via tap.

## Acceptance criteria

- [ ] A full session of the fixture game can be played in the reader (commands, outputs, [MORE]/key prompts).
- [ ] Legacy bundle passes es-check including the engine chunk.
- [ ] Engine chunk not loaded on Home/Library.

## Required tests

**Unit (Vitest)**

- Headless adapter test: load fixture, run a scripted walkthrough, assert expected outputs; status line extraction.

**E2E (Playwright)**

- Open `#/play/fixture-z`, type `look`, see the room description on the last page.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Saves (S1.5), chips (S1.4), downloading real games (S3.4).
