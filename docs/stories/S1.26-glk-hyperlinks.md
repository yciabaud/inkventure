## User story

As a player of a parser game that prints links, I want to tap a link to follow it, so that a game which asks me to
choose a link can be played on an e-reader, where typing is slow.

## Background

The [story-file scan](../reports/story-file-scan-2026-10-04.md) (S7.4, follow-up 5) finds **25 games** that print Glk
hyperlinks. Some of them ask for a link as their input: Bigger Than You Think, Never Gives Up Her Dead, Swigian, Dead
Cities. The [rendering survey](../reports/rendering-survey-2026-10-05.md) finds links in City of Secrets' HELP, in its
upper window. Today the bridge does not declare hyperlink support (`support: ['timer']`, S1.25) and drops the link of
each run (`toRuns`), so links show as plain text and a game that waits only for a link cannot go on.

Both Glk libraries already handle the event: glkote-term's `glkapi.js` (ZVM) and Quixe's `glkapi.js` turn a GlkOte
`hyperlink` event into `evtype_Hyperlink` for a window with a pending hyperlink request.

## Scope

- **Declare** `hyperlinks` in the bridge's `support` list, next to `timer`.
- **Keep the link** of each text run: the GlkOte content item's `hyperlink` value goes into `TextRun` (a new optional
  field), in buffer windows and in the upper-window rows the reader shows as text (status rows, S1.22 menus, S1.23
  boxes).
- **Input request:** when the update's `input` array has `hyperlink: true` for a window, the request says so (a line
  or key request can carry it too, as in Glk). The reader keeps which windows accept links.
- **Reader:** a run with a link is underlined (no colour, e-ink) while its window accepts a link, and plain text
  otherwise (an old turn's links are not tappable). A tap on it sends `{ type: 'hyperlink', window, value }` and
  nothing else: it does not turn the page. A link's tap target is at least 48 px tall (pad the line box, or open a
  dialog listing the page's links when they are too close together: choose and record).
- **Top zone:** a link in the status rows follows the same rule, and a tap elsewhere on the zone still opens the
  reader menu.
- **Transcript view and saves:** links are kept as plain text (no tap).
- SPEC §3.6 (Reader) and §4.2 (bridge) updated.

## Acceptance criteria

- [ ] A Glulx and a Z-machine fixture that wait for a link: tapping a link sends it and the game answers; a line
      typed in the command bar still works when the game also waits for a line.
- [ ] Links of an earlier turn, or printed while the game does not ask for one, are plain text and a tap on them
      turns the page as before.
- [ ] One of the games named above (Bigger Than You Think or Swigian) can be started and played past its first link.
- [ ] Every link target is at least 48 px; no other tap zone changes.
- [ ] Checked on the PR preview and on the Kindle.

## Required tests

**Unit (Vitest)**

- Bridge: `support` lists `hyperlinks`; a content item with `hyperlink` keeps its value in the run; an `input` entry
  with `hyperlink: true` reaches the input request; sending a link produces the GlkOte event with the window and
  value and the current generation.

**E2E (Playwright)**

- A new fixture room (in `lamp.inf`, both builds) with a few links (`glk_set_hyperlink`) and a hyperlink request: tap
  one, the game answers; a link of the previous turn is not tappable.

Plus the global gates: lint, `es-check es5` on the legacy bundle, size budgets, CI green.

## Out of scope

- Links in graphics windows or in pictures.
- Twine and ink (their links and choices already work).
- Making the IFDB or web links a game prints open a browser page.
