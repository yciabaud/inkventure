## User story

As a player with several devices, I want to export my saves as a code and import it elsewhere so that I never lose progress.

## Scope

- Export: compressed JSON of prefs/home/progress/saves → base64 in readable chunks; copy button; `.txt` download when supported.
- Import: paste code, validate (version, checksum), preview, merge or overwrite.
- Optional reminder to export after N named saves.

## Acceptance criteria

- [x] Export on one profile + import on a fresh one restores home, progress and saves exactly.

## Required tests

**Unit (Vitest)**

- Codec round-trip, checksum failure, merge vs overwrite rules, version mismatch.

**E2E (Playwright)**

- Export in context A, import in fresh context B, Continue resumes the same turn.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Cloud sync.

## Notes & decisions

- **Where:** Settings › Data has *Export my data* and *Import* buttons opening two more pages
  (`#/settings?s=export|import`) whose "‹" goes back to Data. Every page (the import preview included) fits the baseline
  636×740 screen in English and French without scrolling; the code sits in a fixed-height box.
- **Code format** (`src/storage/transfer.ts`, lazy chunk ≈ 2 KiB gz): a header `INKVENTURE 1 <CRC-32 hex>`, then the
  base64 of the deflated JSON `{schema, date, entries}` in groups of 8 characters, 6 groups a line. Decoding ignores
  all whitespace (pastes that re-wrap or flatten lines still work). The CRC-32 is over the deflated bytes. Errors:
  *empty*, *format* (not an Inkventure code, or an older unknown format version), *checksum* (damaged or incomplete),
  *newer* (format version or storage schema newer than this app: "refresh the page").
- **What is exported:** `prefs`, `home`, `progress:*`, `save:*:auto` and named slots, stored values as they are
  (saves stay deflated inside, so the outer deflate gains little on them). Cached story files and the LRU list are not
  exported. Unknown keys or values of the wrong shape in a code are dropped on import.
- **Merge rules:** this device's prefs win (the code only fills in missing fields); My adventures is the union, sorted by
  `added` (this device's entry wins for a game on both); a progress record (`lastPlayed`), autosave or named slot
  (`date`) present on both sides is the newer one, this device's on a tie. **Overwrite** makes the exportable entries
  exactly the code's (entries the code lacks are deleted; cached files kept). The preview lists what the code holds
  and, per choice, how many named saves on this device would be replaced or lost.
- **All or nothing:** `applyImport` deletes first (to make room), then writes; on a `StorageFullError` it puts back
  every changed entry, including autosaves the store evicted to make room, and the page says nothing was changed.
- **After import:** the locale is re-applied (the code may bring a language) and Home is shown, where Continue resumes
  the imported game at its turn (e2e: export in context A, import in a fresh context B, Continue → same move count,
  and the named slot restores).
- **Copy / file:** *Copy* uses `navigator.clipboard.writeText`, falling back to selecting the box and
  `execCommand('copy')`; if both fail, it says to copy by hand. *Save as a file* (`inkventure-YYYY-MM-DD.txt`) is only
  shown where `a[download]` and object URLs exist. Import can also *Open a file…* (`FileReader`, present on the
  measured Kindle). Whether copy, download and file picking work on the Kindle is to be checked in S7.1.
- **Not done:** the optional reminder to export after N named saves — left as a follow-up idea.
