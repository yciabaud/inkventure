## User story

As a player, I want my progress stored safely on my device so that I never lose a game because of a full storage.

## Scope

- `src/storage/`: typed get/set/remove over localStorage with `ik:v1:` prefix; in-memory fallback if localStorage is unavailable (with a warning flag).
- Schema version key + migration runner.
- Quota handling: catch `QuotaExceededError`, evict per SPEC §6.1 priority (cached files LRU → stale autosaves), never evict named saves silently; surface an error for the UI.
- Compression helper (deflate + base64) for saves.
- Prefs store (UI language, reader defaults) wired into i18n from S0.5 if merged.

## Acceptance criteria

- [x] All app persistence goes through this layer (lint rule or code review guard against direct `localStorage`).
- [x] Behaviour with storage disabled: app still runs, shows a non-blocking warning.

## Required tests

**Unit (Vitest)**

- Get/set round-trip, migrations, LRU ordering, eviction order under simulated quota, named saves never evicted, compression round-trip.

**E2E (Playwright)**

- Pref persists across reload (e.g. locale override set via test hook).

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Export/import UI (S5.2).
- IndexedDB enhancement.

## Notes & decisions

- **Modules** (`src/storage/`): `backend.ts` (Web Storage subset, `MemoryBackend` with a simulated quota,
  `isQuotaError`, `openBackend`), `keys.ts` (SPEC §6.1 key helpers; slot `auto` is reserved), `store.ts`
  (`createStore`: JSON get/set/remove under `ik:v1:`, LRU, eviction, events), `migrations.ts` (`ik:schema` + ordered
  `MIGRATIONS`), `compress.ts`, `prefs.ts`, and `index.ts` with the app-wide `getStore()` singleton.
- **Guard**: the ESLint `no-restricted-globals` / `no-restricted-properties` rule from S0.1 forbids `localStorage` and
  `sessionStorage` outside `src/storage/`.
- **Fallback**: `openBackend` probes a write; if `localStorage` is missing or throws, an in-memory backend is used and
  `store.persistent` is `false`. A storage that is merely *full* (quota error with existing data) is kept, so the
  data stays reachable. `StorageNotice` (in `.app__main`, `role="status"`, dismissable) warns when storage is not
  persistent, and when a write fails because storage is full (with a *Manage data* link to Settings, which S5.1/S5.2
  will fill in).
- **Eviction order** on a quota error, retried until the write fits: (1) cached story files `file:*`, least recently
  used first (files missing from `ik:v1:lru` go first); (2) autosaves whose `progress:<tuid>.lastPlayed` is more than
  90 days old, oldest first. Autosaves with no known `lastPlayed`, recent autosaves, named saves, prefs, home and
  progress are never evicted, nor the key being written. When nothing is left the store emits `{ type: 'full' }` and
  throws a `StorageFullError` (`isStorageFullError()`); each eviction emits `{ type: 'evicted', key, reason }`.
  `progress` is expected to carry `lastPlayed` as a millisecond timestamp (S1.5).
- **LRU list** (`ik:v1:lru`) tracks files and autosaves, oldest first, updated on every get/set/remove of those keys.
  It is advisory: a failure to write it never fails the caller's write.
- **Migrations**: version 1 is the initial layout and `MIGRATIONS` is empty. A fresh storage is stamped with the latest
  version without running anything; a newer stored version (rollback) is left alone; the version is saved after each
  step, and a failing migration stops there (logged) without blocking the app.
- **Compression**: `fflate` (`deflateSync`/`inflateSync`, MIT) + chunked `btoa`. It is deliberately *not* re-exported
  from `src/storage/index.ts`, so the library stays out of the initial bundle until S1.5 imports
  `src/storage/compress.ts` (ideally lazily). fflate relies on typed arrays: to confirm on the Kindle in S0.3.
- **Legacy bundle**: +3.6 KiB gz. `StorageFullError` is a plain `Error` with a `name` rather than a subclass, and loops
  avoid `for…of`, because Babel's helpers for those pulled several KiB of core-js polyfills into the legacy bundle.
- **Prefs**: `Prefs = { locale?, reader?, libraryView? }`, `getPrefs(store)` / `setPrefs(store, patch)` (shallow
  merge; `undefined` removes a field). S0.5 is not merged yet, so wiring the locale override into i18n moves to S0.5
  (its scope was updated). Reader defaults are typed loosely until S1.2.
- **Test hook**: `window.__inkventure` (`getPrefs`, `setPrefs`, `persistent`), installed in `main.tsx`, lets the e2e
  test set a pref and read it back after a reload. The storage-disabled e2e test makes `localStorage` throw and
  checks the app still navigates, shows the warning (tap target ≥ 48 px, no overflow) and can dismiss it.
