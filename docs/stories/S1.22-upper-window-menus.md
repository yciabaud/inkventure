## User story

As a player on an e-reader, I want to read and browse a game's help menu when the game draws it in its upper window,
so that I can open its subjects (about, how to play, hints) as I would in any interpreter.

## Background

Reported by the owner on 2026-10-03, on the Kindle, while checking S5.3 (the same happens online). In **Lost Pig**,
HELP opens a menu drawn entirely in the upper window (the Inform menu library's style): a title, a legend, then the
subjects, the selected one marked with `>`:

```
                         Lost Pig
N = next subject                          P = previous
RETURN = read subject                   Q = resume game
                     > About this game
               How to play Interactive Fiction
                Special commands for this game
                           Credits
                            Hints
```

Since S1.15 the top zone shows at most 3 rows then "…": the player sees the legend but not the subjects, and the text
area still shows the previous turn and `>help`. The full list is only in the reader menu (⋯), where the centred
subjects are split as if they were the right part of a status line. The key chips (N, P, Return, Q, from S1.12) work,
but the player cannot see what they select.

[S1.16](S1.16-cleared-screens-and-menus.md) made menus drawn in the **main** window usable (the fixture's MENU,
Bronze's HELP). Menus drawn in the **upper** window are not covered.

## Scope

- **Detect an upper-window screen:** the game waits for a key (or a line) while its upper window has more rows than
  the top zone shows (more than 4 non-empty rows). Choose and record the rule (e.g. also: the main window was cleared,
  or the upper window takes most of the screen), so that ordinary multi-row status windows (S1.15: Bronze's compass,
  Counterfeit Monkey) stay in the top zone.
- **Show it in the text area**, as a screen of its own (like S1.16's replaced screens: one screen, not a page per key,
  replaced at each key; kept in the Transcript view):
  - the rows in order, blank rows dropped;
  - a row the game centred stays centred (a row with one part and wide margins on both sides), instead of being split
    into a left and a right part;
  - the selected subject (`>` or reverse video, as the game marks it) stands out (bold).
- While it shows, the top zone keeps only the first row (the title), or nothing.
- Back to normal when the game returns to the main window (Q: "resume game"), on a fresh page as in S1.16.
- Subjects opened with Return (text in the main window) read as they do today.
- SPEC §3.6 (status line and single-key prompts) updated.

## Acceptance criteria

- [ ] Lost Pig: HELP shows the menu's subjects in the text area, the selected one in bold; N / P move the selection on
      the same screen (no page added); Return opens a subject; Q returns to the game.
- [ ] A centred row stays centred, in the text area and in the reader menu's list of status rows.
- [ ] Games with an ordinary multi-row status window (Bronze, Counterfeit Monkey, the fixtures) are unchanged.
- [ ] Checked on the PR preview and on the Kindle, or the Notes say why not.

## Required tests

**Unit (Vitest)**

- Detection: an upper-window menu (title, legend, subjects) vs a 2–4 row status window vs a quote box.
- Rows: centred rows recognised, the selected subject found (`>` marker), blank rows dropped.

**E2E (Playwright)**

- Extend the Z-machine fixture (`tests/fixtures/zmachine/lamp.inf`, rebuilt and committed) with a menu drawn in the
  upper window (title, legend, 3 subjects, `@read_char`): the subjects show in the text area, N moves the selection
  without adding a page, Return opens a subject, Q returns to the game on a fresh page.

Plus the global gates: lint, `es-check es5` on the legacy bundle, size budgets, CI green.

## Out of scope

- Drawing the upper window as a full grid (fixed columns, reverse video, colours).
- Tapping a subject to select it (the key chips do it); a possible follow-up.
- Menus drawn in the main window (S1.16).
