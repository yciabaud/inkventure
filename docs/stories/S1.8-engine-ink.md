## User story

As a reader who prefers choices to typing, I want to play Ink stories with big choice buttons so that playing on e-ink is effortless.

## Scope

- inkjs adapter implementing `Engine` (choices → `ChoiceInput`).
- Choice buttons on the last page; no command bar.
- Save/restore via ink state JSON; undo via previous state.
- Ink fixture story.

## Acceptance criteria

- [x] Fixture Ink story playable to an ending using taps only; resume after reload.

## Required tests

**Unit (Vitest)**

- Adapter: choices, state save/restore, tags → status line title.

**E2E (Playwright)**

- Pick choices, reload, continue from same point.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Ink external functions beyond basic ones.

## Notes & decisions

- **inkjs 2.4.0** (MIT, pinned), runtime only (`inkjs` → `dist/ink.mjs`, no compiler): the engine chunk is 32 KiB gz
  (37 KiB legacy). Ink stories are compiled JSON; inklecate's byte order mark is skipped.
- **Engine** (`src/engines/ink/inkEngine.ts`): runs `Continue()` line by line until the story stops, then asks for a
  `ChoiceInput` (or exits at the end). The choice made is echoed as an `input` paragraph (bold), so it opens the next
  turn like a command. Typed lines and keys are ignored.
- **Status line:** the `title:` global tag on the left, the latest `chapter:` line tag on the right (the chapter alone
  when there is no title; the catalogue title when neither).
- **Saves:** `story.state.toJson()` in a JSON envelope (`inkventure-ink` v1) naming the story by a hash of its JSON, with
  the current chapter; a bad state leaves the story as it was. Engine `undo()` returns false: the reader's Undo restores
  its previous turn snapshot. A turn (snapshot + autosave) now begins at each choice as well as each command; Save… is
  enabled while choices are offered.
- **Choice buttons** (`src/screens/reader/ChoiceList.tsx`): numbered full-width buttons (≥ 48 px) in the slot under the
  text of the last page. The slot is sized to the list's measured height (long choices wrap), re-measured on resize,
  capped at 60 % of the screen (the list scrolls past that, a last resort). CSS classes `story-choice*` (the library
  filters already use `choice*`).
- **External functions:** `allowExternalFunctionFallbacks` (the ink function of the same name is used); none is bound.
  A runtime error of the story goes to `onError` (the reader's error page); ink warnings are only logged.
- **Fixture:** `tests/fixtures/ink/lamp.ink` → `lamp.json` (the Lamp at Saltmere with choices, two endings), compiled by
  `scripts/fixtures/build-ink.sh` with inkjs's own compiler; served at `#/play/fixture-ink`.
- **Ink enabled in the catalogue** (`scripts/catalog/playability.json`); the sample catalogue has no ink game, so it is
  unchanged. The e2e test "a format without an engine yet" now uses a Twine game. About credits inkjs.
