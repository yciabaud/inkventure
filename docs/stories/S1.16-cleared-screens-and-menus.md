## User story

As a player browsing a game's menu (help, hints, options), I want to see only the current menu screen, so that I
don't page through every earlier copy of it.

## Background

Found on 2026-10-01 (Bronze `HELP`, production vs Parchment). An Inform menu clears the main window and redraws
itself after each key. Parchment honours the clear: one screen, always in the same place. The reader ignores
`clear` blocks ("the paginated transcript keeps everything", SPEC §4.2), so every redraw of the menu and every
topic is **appended**. In a few key presses the page count went from 4/4 to 7/7, and after each key the reader shows
an earlier page with "Back to the present ›" to tap. It is confusing, and each extra tap costs an e-ink refresh.

## Scope

- A `clear` block starts a new screen: the reader opens the next output on a fresh page, and the text before it is
  no longer on the same page.
- **Screens with only key presses in between** (no command, no choice: a menu being browsed) replace each other
  in the paged view. When the game goes back to line input, only the last screen before it stays in the pages.
  Decide and record whether the Transcript view keeps the replaced screens.
- The reader shows the latest screen at once, with no "Back to the present" step, when the new screen fits on one
  page.
- Autosave and undo are unchanged: snapshots are still taken on line input only.
- SPEC §3.6 / §4.2 updated (`clear` no longer ignored).

## Acceptance criteria

- [ ] Bronze `HELP`: moving through the topics (N / P / Return) and back (Q) never adds pages. After Q, the game
      text and the pages before `HELP` are as they were, plus the menu's last screen if decided so.
- [ ] A game that clears the screen once (e.g. after its title) shows the new text on a fresh page.
- [ ] Resume after reload and the Transcript view still work.

## Required tests

**Unit (Vitest)**

- Transcript building with `clear` blocks: new screen, key-only screens replacing each other, line input closing
  the run.

**E2E (Playwright)**

- Extend the Z-machine fixture with a small menu (`erase_window`, a 3-row upper window with a legend, `@read_char`
  N / P / Q, two topics). Browse it with the key chips: the page count does not grow, Q returns to the game, and
  the game's earlier text is still on the earlier pages.

Plus the global gates: lint, `es-check es5` on the legacy bundle, size budgets, CI green.

## Out of scope

- Real-time or animated screens (status bars that redraw on a timer).
- Drawing the upper window as a full-screen grid.
