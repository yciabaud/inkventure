## User story

As a player, I want the library to only show games I can actually play, without adult content, so that every tap on Play works.

## Scope

- Fetch `viewgame?json` per candidate; extract links, formats, IFID, genre, language, forgiveness, tags, cover, playtime.
- Choose the best playable file (format priority, IF Archive preference, zip containing a single story file).
- Compute `slow` flag (heuristic from S1.7 or provisional: Glulx > 1 MB).
- Content policy: `CONTENT_POLICY` env, tag denylist + manual exclude list in `scripts/catalog/content-policy.json`.
- Report of dropped games with reasons.

## Acceptance criteria

- [x] Every kept game has a supported file URL; adult-tagged fixtures are excluded; report lists reasons.

## Notes & decisions

- **Code**: `scripts/catalog/resolver.ts` (pure), `resolve.ts` (CLI, `npm run catalog:resolve`), `summary.ts`
  (Markdown summary), configs `playability.json` (enabled formats) and `content-policy.json`. Usage in
  `scripts/catalog/README.md`.
- **No fetch here**: the crawler (S2.1) already stores each game's `viewgame?json` record, so resolution is offline and
  deterministic over `data/raw/games.json`.
- **Formats from IFDB's source**: link format ids `zcode`, `blorb/zcode`, `glulx`, `blorb/glulx`, `hypertextgame` (web
  games); zips carry `compression` and `compressedPrimary` (the story file inside). Twine = `hypertextgame` HTML from a
  Twine development system; ink = a compiled `.json` (web exports of ink games are not playable by inkjs as such).
- **Only engines that exist**: `playability.json` enables `zcode` alone for now; Glulx, ink and Twine games are counted
  (`format-not-enabled`) and appear once S1.7–S1.9 enable them. SPEC §5.2 says the library shows only games the app can
  run.
- **Best file**: enabled format order, IF Archive first (CORS verified in S0.3), uncompressed, blorb, IFDB order. Zips
  only with a named primary file (the loader, S3.4, will unzip with fflate). IF Archive `http://` links are upgraded;
  other plain-HTTP links are refused (mixed content on an HTTPS page).
- **Language**: IFDB sends the code in brackets (`English (en-US)` → `en-US`) or, without one, the whole field
  (`English`); both reduce to the primary subtag, with a small map of language names.
- **`slow`**: file sizes are not in the API, so the provisional rule is every Glulx game (S1.7 will refine).
- **Not in the JSON API**: forgiveness (only in the iFiction XML) and licence. Follow-up if the Library needs the
  forgiveness filter: fetch `viewgame?ifiction` or use `forgiveness:` searches.
- **Error format**: viewgame errors are `{errorCode, errorMessage}` (search errors are `{error}`); the crawler now
  recognises both and the fixture uses the viewgame form.
- **Fixtures**: 11 synthetic games covering every drop reason, a zip with a primary file, an HTTP IF Archive link, a
  language name without code, several genres.
- **Live check**: the manual workflow now also resolves and writes the raw field distributions (link formats,
  compression, languages, genres) to the job summary.
- **First live sample** (manual workflow, 100 records from the first 2 search pages of each query): 23 kept (all
  Z-code), 48 `unsupported-format` (mostly `hypertextgame` links: online-play pages, not files), 15
  `format-not-enabled` (6 Glulx, 9 Twine), 9 `adult-content`, 4 `insecure-url`, 1 `no-game-file`. Real language values
  include several languages with their codes together (`Castilian, English (es, en)`), region subtags (`en-GB`,
  `es-AR`, `zh-Hans`); the resolver takes the first code in brackets. Genres are free text, often `A/B`.
