## User story

As a developer, I want a probe page that reports what the e-reader browser supports so that the assumptions in SPEC §2.2 are replaced by facts.

## Scope

- Standalone ES3/ES5 page `public/probe.html` (no framework, no build dependency).
- Detects and displays: deployed build (`version.json` commit and date, S0.2), user agent, viewport/devicePixelRatio, ES features (Promise, fetch, arrow functions via `new Function`, typed arrays), XHR `arraybuffer`, localStorage (write/read, approximate quota), IndexedDB, Service Worker, CSS flexbox/grid/variables/filter, touch & swipe events, font loading, `Intl`.
- Timing micro-benchmark (e.g. 1e6 loop iterations, JSON.parse of a 150 KB file).
- Real load timing of the app on the device: time to first render of Home and total bytes transferred (Navigation/Resource Timing when available, else a timestamp in `index.html` vs first render), and which font format (`.woff` / `.woff2`) is actually downloaded — to validate the budgets of S0.7.
- Tests XHR to IF Archive (a known small file) and to IFDB API to record CORS behaviour.
- Result shown as a copyable text block (to paste into an issue) and a large QR code of the result if feasible.

## Acceptance criteria

- [x] Probe runs on the Kindle experimental browser without script errors.
- [x] Results for at least one Kindle and (if available) one Kobo recorded in `docs/device-reports/` and SPEC §2.2 / §13 updated accordingly.

## Notes & decisions

- **First device report** (2026-09-29, Kindle experimental browser, `docs/device-reports/2026-09-29-kindle.txt`):
  ran without script errors. Key findings: modern engine behind the old `Kindle/3.0+` user agent (ES2017, no
  `?.`, no WebAssembly) that loads the **modern** bundle; IF Archive and mirror CORS **ok**; IFDB API blocked;
  Home renders in ~1.1 s; localStorage ~4.75M chars; SW / IndexedDB / Cache API present; all modern CSS supported;
  `ontouchstart` absent but touch/pointer events fire; fonts fetched as woff2. No Kobo report yet.
- **Updated from it**: SPEC §2.1–2.2 (measured capabilities; ES5 bundle and conservative CSS kept for older
  e-readers), §5.5 (IF Archive CORS verified), §6.2 and §13 (#1–3 updated, #11 offline follow-up); S0.7 note
  (woff2), S1.1 scope (swipe detection without `ontouchstart`), S3.4 scope (CORS already verified).
- **Second report after sleep / wake** (`docs/device-reports/2026-09-29-kindle-after-sleep.txt`, not a restart):
  `run #4` with the same first-run date, so localStorage is kept across sleep. Results otherwise identical; the loop benchmark
  varied from 277 to 454 ms between runs, so perf numbers should be read as ranges.
- **Still open**: localStorage persistence across a real browser / device restart; older Kindle firmware and Kobo
  reports — the probe stays available for them.
- The code part was PR #9.
- **Location**: `public/probe/` (copied as-is by Vite, served at `/inkventure/probe/` — short to type on a Kindle)
  rather than `public/probe.html`. `index.html` + `probe.js` (hand-written ES5, IIFE, no build) + `qrcode.js`
  (vendored [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) 2.0.4, MIT, ES5, only loaded by
  the probe). `check:es5` now also covers `dist/probe/*.js`; ESLint lints `probe.js` as ES5 script; Prettier uses
  `trailingComma: "none"` there (trailing commas in calls are ES2017).
- **Checks**: build (`version.json`), device (UA, languages, viewport, screen, DPR), JS syntax via `new Function`
  and built-ins, `Intl`, web APIs (hashchange, IndexedDB, Service Worker, Cache API, `document.fonts`, Resource
  Timing), localStorage (read/write, **persistence across runs** via `ik-probe:runs`, approximate quota by filling
  256K-char chunks up to 20M chars, then cleaning up), CSS (flexbox incl. `-webkit-box`, grid, custom properties,
  `filter`, `object-fit`, `calc`, `vw`, hyphens, `position: fixed`), input (touch/pointer support + a swipe box that
  reports tap vs. left/right), perf (1e6 loop, JSON of ~150 KB, layout of 300 paragraphs), network (XHR
  `arraybuffer`, CORS to `ifarchive.org` and `mirror.ifarchive.org` with `9:05` (`905.z5`), IFDB JSON API, IFDB cover
  thumbnail as an image), and **the real app** loaded in an off-screen iframe: time to first render of Home, legacy
  (SystemJS) vs. modern bundle, resources/bytes and font format actually fetched (Resource Timing when available).
- **Direct `localStorage` use** in the probe is deliberate (it measures the raw API); the "go through
  `src/storage/`" rule applies to the app in `src/`. Probe keys use their own `ik-probe:` prefix.
- **Report**: plain `key: value` lines, shown in a `<pre>`, a read-only textarea to copy, and on demand as QR codes
  split into ~900-character parts (*Part i/n*), encoded as UTF-8 — a single ~2 KB code was too dense for e-ink.
  Verified locally by decoding all parts with jsQR: the concatenation equals the report exactly.
- **E2E** (`tests/e2e/probe.spec.ts`, network mocked: IF Archive blocked, mirror allowed with CORS, IFDB API
  blocked, cover served): every section present with the expected values, no script errors, copy box = report,
  quota keys cleaned up, multi-part QR shown; a reload reports `run #2`; the swipe box records a tap on touch
  projects.
- `docs/device-reports/README.md` explains how to run the probe on a Kindle/Kobo, how to send and record the
  report, and how to read each line.
