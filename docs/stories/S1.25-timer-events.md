## User story

As a player of a game that does something on a clock (text that appears by itself, a countdown, an animation), I want
that to happen on my e-reader, so that the game plays as its author meant, and never waits forever.

## Background

The [story-file scan of 2026-10-04](../reports/story-file-scan-2026-10-04.md) (S7.4) found **116 games** that use time:
85 Z-machine games with timed input (`read_char` / `aread` with a time and a routine, e.g. Shrapnel, Fail-Safe, Make It
Good) and 31 Glulx games that request timer events (e.g. Best of Three, NewGrant, Los alegres hombres de Sherwood,
which start a 10–40 ms timer at their intro, for animations). The reader never sends a timer: the GlkOte bridge
declares no optional feature (`support: []`), and ZVM's timed input is given no time. Whatever a game does on a clock
does not happen. Most games treat time as optional, but some wait for it.

On e-ink, a fast timer would redraw the screen many times a second: it must be slowed down.

## Scope

- **Glulx:** the bridge declares `timer` support and sends timer events, at the interval the game asks for but **never
  more often than once a second**; no timer while the reader is not on the game (another screen, the app hidden).
- **Z-machine:** timed input calls its routine on time (ZVM / glkote-term), with the same floor; check what ZVM does
  with the time today.
- **Redraws:** text or status rows that arrive on a timer are shown without moving the reader off the page being read
  (only on the last page, as a turn's text is).
- Choose and record what a game that animates (redraws every tick) looks like on the Kindle; a game may need its timer
  slowed further, or ignored, if it hurts the e-ink screen.
- SPEC §4 and §3.6 updated.

## Acceptance criteria

- [x] A fixture with a timer (Z-machine timed `read_char`, Glulx timer): text appears after its delay, without a key.
- [ ] Shrapnel, Fail-Safe (Z-machine) and Best of Three (Glulx): their timed events happen (survey replay or by hand).
- [x] No timer events faster than once a second; none while the reader is not on the game.
- [ ] Checked on the PR preview and on the Kindle (screen refreshes acceptable), or the Notes say why not.

## Required tests

**Unit (Vitest)**

- The bridge: `timer` declared, timer events sent at the requested interval with the 1 s floor, stopped on request (0).
- ZVM: timed `read_char` calls its routine.

**E2E (Playwright)**

- Fixture games (extend `lamp.inf`, Z-machine and Glulx, rebuilt and committed): a command whose text appears after a
  delay, with a fake clock (`page.clock`).

Plus the global gates: lint, `es-check es5` on the legacy bundle, size budgets, CI green.

## Out of scope

- Sound (silent by design).
- Graphics windows and their animations.

## Notes & decisions

- **Bridge** (`glkote-bridge/bridge.ts`): declares `timer` (glkote-term's Glk library asks GlkOte; Quixe's always said
  yes but never got an event) and sends `{type: 'timer'}` at the interval of the update's `timer` field, floored to
  `MIN_TIMER_MS` = 1 s, re-armed after each event; `null` or 0 stops it. A tick comes only while the VM waits (an update
  since its last event): during a sliced Glulx run it is skipped. `setTimersActive(false)` stops it and `true` re-arms
  a full interval later; `dispose()` for a VM replaced by restore / restart, or that failed to start.
- **ZVM timed input** (`zvm/timedInput.ts`): ifvms 1.1.6 ignores the time and routine of `@read` / `@read_char` (a TODO
  upstream, and ZVM is frozen there). Wrapped per VM instance at runtime rather than patched at build time, so the unit
  tests (which load ZVM unpatched) run it. The routine runs nested in the waiting VM: called with its result stored on
  the stack, then run until the frame depth is back (ZVM's compiled branches to "return true" call `e.ret` themselves,
  so a return is not always seen by the run loop). A pending line request is cancelled while it runs (Glk cannot print
  in a window waiting for a line), with its echo turned off so no blank line is printed, and asked again with what was
  typed when the routine returns false. When it returns true the timer event becomes the input: terminator 0, or
  key 0. A routine that waits for input itself is a fatal error (none seen).
- **Found on the way:** ZVM stored glkapi's terminator 0 for a line ended by Return (it only defaulted to 13 on
  `NaN`). Harmless until now, but a game that reads the terminator of a timed line would think its routine ended it:
  Return is now 13.
- **Reader:** `GameReader` turns timers on only while it shows the game (`playing`, the game view, no dialog, the page
  visible: `visibilitychange`), and off when it unmounts. `PagedText` gets `keepPage`: new blocks with the same
  `focus` as before keep the page being read, so text on a timer goes to the end without moving the reader (a new
  turn, a restore or a new screen still change `focus` and move it).
- **Fixtures:** TIDE (Z-machine: `@read_char 1 20 TideTick`; Glulx: `glk_request_timer_events(2000)` with a char
  request), BELL (Z-machine only: `@aread` with a time, the routine prints, the third ring ends the line). Rebuilt
  with Inform 6.41 (Debian `inform6-compiler`, and the 6.12.2 library from GitHub for Glulx).
- **Games** (headless, with the app's engines and fake timers): **Shrapnel**'s intro is a timed `@read_char` of 0.4 s
  (1 s here) whose routine alternates the upper window ("*** You have died ***" / the room's text) six times, then ends
  the prompt on the title: it now plays as meant. **Best of Three** asks for a 10 ms timer at its intro and keeps it
  for the whole game (an animation of its graphics window, not drawn): one event a second, which prints nothing; the
  game plays normally. **Fail-Safe**'s 7 timed reads come later in play (S7.4 scan) and were not reached in the
  first turns played headless: to check by hand on the preview.
- **Animated boxes** (found on the PR preview, on a phone): Shrapnel's intro redraws a centred row of its upper window
  at each tick, which the reader read as a new box each time (S1.23) and kept them all, stacked in the text. The
  bridge now marks the `status` / `quote` blocks drawn on a timer (`timer`), and a box replaced by another box on a
  timer is dropped instead of kept: one frame at a time, and the last one (the title) stays once the game goes on. A
  box a timer only takes away is still kept.
- **Animations on e-ink:** one redraw a second at most, and only when the event changes the text or the status rows
  (an event that prints nothing changes nothing on screen). Shrapnel's intro is six such redraws. No game was found
  that needs its timer slowed further or ignored.
- **Tests:** the e2e tests fake the page clock (`page.clock`), then pause it to move it by hand. Effects run after a
  frame, which the paused clock holds back too: after leaving the Transcript view the test moves the clock 100 ms first.
- **Closed on 2026-10-09** by the owner, before tagging v1.0.0, with two criteria left unticked: Fail-Safe's timed
  reads were not reached (Shrapnel and Best of Three were), and no check on the Kindle is recorded (the PR preview was
  checked on a phone).
