## User story

As a player of a Z-machine game, I want the game to go on when I type RESTORE or press R where it offers to restore,
so that it never freezes (the reader's menu is where saves are restored).

## Background

Found by the rendering survey's replay of 2026-10-04 (S7.4, [report](../reports/rendering-survey-2026-10-04.md)):
SameGame stops with `TypeError: Cannot read properties of null (reading 'ref')`. The GlkOte bridge answers a game's
own file prompts (SAVE, RESTORE, SCRIPT) with no file, so that saves go through the reader's menu. For a prompt that
**reads** a file, glkote-term's glkapi (`gli_fileref_create_by_prompt_callback`, used by ZVM) then calls
`Dialog.file_ref_exists(fref.ref)` on a null `fref` and throws in a timer: the game never resumes. Reproduced with the
fixture: `restore` in `lamp.z5` leaves the game with no prompt. Quixe's glkapi (Glulx) checks for a null file and is
not affected.

It happens whenever a player types RESTORE in a Z-machine game, or presses R where a game offers to restore at its
start (SameGame; Anchorhead, a featured game, offers it too).

## Scope

- A vendor patch (`scripts/build/vendor-patches.ts`) to glkote-term's glkapi: skip the "file exists" check when there
  is no file, as Quixe does; the game is told the restore failed and goes on ("Restore failed." or the game's own
  message).
- The game's RESTORE then says where saves are (the reader's menu), if the reader already shows such a hint for SAVE
  (check; else out of scope).

## Acceptance criteria

- [x] In the Z-machine fixture, `restore` answers (the library's failure message) and the next command plays.
- [x] SameGame and Anchorhead (R at their start) go on.
- [ ] Checked on the PR preview and on the Kindle, or the Notes say why not.

## Required tests

**Unit (Vitest)**

- The vendor patch applies (`vendor-patches.test.ts`) and the ZVM adapter test plays `restore` then `look` on the
  fixture with no error.

**E2E (Playwright)**

- The Z-machine fixture: type `restore`, then `look`: the game answers both.

Plus the global gates: lint, `es-check es5` on the legacy bundle, size budgets, CI green.

## Out of scope

- Restoring a game's own save files (saves go through the reader's menu, S1.5).

## Notes & decisions

- **The patch** (`scripts/build/vendor-patches.ts`, glkote-term's `glkapi.js`): `if ( fref && ui_specialinput.filemode
  === 'read' && !Dialog.file_ref_exists( fref.ref ) )`, as Quixe's glkapi already does. With no file, ZVM's `@restore`
  fails: the Inform library prints "Restore failed." and asks for the next command. The SAVE prompt (a file to write)
  never reached that check and was not affected.
- **No hint in the game's text** (scope's second point): the reader shows none for SAVE either; its menu is where saves
  are. Left as it is.
- **Checked:** the fixture (unit and e2e: the e2e fails without the patch); SameGame, which stopped on an engine error
  in the survey, now plays its script (`npm run survey:rendering -- --only ph0y9c8b9ugvxdrv`); Anchorhead, R at its
  start: "Restore failed" is not shown (its own message), the game starts.
