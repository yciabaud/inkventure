## User story

As a player, I want to try Twine stories so that popular choice-based games are available too.

## Scope

- Load Twine HTML into `<iframe sandbox="allow-scripts">` via blob/srcdoc.
- Inject e-ink stylesheet and page-turn helper; fallback to scrolling inside the iframe if pagination fails.
- "Experimental" badge; Inkventure save slots disabled; story format's own save used.
- Twine fixture (Harlowe and SugarCube samples).

## Acceptance criteria

- [x] Both fixtures readable and playable to an ending on the ereader projects.
- [x] No script from the story can access the parent page (sandbox verified).

## Required tests

**Unit (Vitest)**

- Stylesheet injector and HTML preparation helpers.

**E2E (Playwright)**

- Open Harlowe fixture, click a link, text changes; parent storage untouched.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Full pagination for every story format.

## Notes & decisions

- **No `Engine`:** a Twine story runs its own story format, so it does not fit the engine interface (no output blocks,
  no input requests). `TwineReader` (`src/screens/reader/`, a lazy chunk behind `LazyTwineReader`) shows it in
  `<iframe sandbox="allow-scripts" srcdoc>` inside the usual reader chrome; `isAvailable('twine')` is true and
  `loadEngine('twine')` still rejects. First load grew by 0.6 KiB gz (191.5 / 200 KiB): the frame script and the page
  preparation are in the lazy `twineHtml` chunk.
- **Sandbox:** scripts only, opaque origin. The e2e test checks from inside the frame that `parent.document`,
  `parent.localStorage`, `top.location` and `document.cookie` all throw, and that the page's storage only gains the
  reader's own `ik:` entries. WebKit gives an opaque origin an empty cookie jar instead of throwing, so the frame
  script makes `document.cookie` throw everywhere.
- **Listening before the frame starts:** the reader's message listener and the handlers it calls are set in layout
  effects. WebKit can load the srcdoc frame before passive effects run; its first page report (sent once) was lost and
  the story never joined My adventures.
- **CodeQL:** the minified Harlowe / SugarCube code inside the built fixtures raised 8 alerts (string escaping,
  prototype pollution); building them at install keeps that third-party code out of the repository.
- **Storage stand-in** (beyond the scope's wording, needed for "story format's own save used"): in the sandbox the real
  `localStorage` / `sessionStorage` throw, so the story formats could not save at all. The injected script replaces
  them with in-memory stores seeded with what the reader kept, and posts every change (one message per area and tick);
  the reader writes it, debounced by 1 s and on leaving, under `save:<tuid>:twine` through `src/storage/twine.ts`
  (at most 1 M characters, a named-save entry: never evicted, removed with the game's saves). Harlowe's and SugarCube's
  save slots therefore persist, and a SugarCube story resumes where it was after a reload (its session). Harlowe keeps
  no session: it starts again on reload unless the player saved.
- **E-ink stylesheet:** `!important` rules over the format's own: black on white, the reader's "Aa" settings with system
  fonts (the app's web fonts are not reachable from the opaque origin), bold underlined links ≥ 48 px, no animations or
  transitions, SugarCube's UI bar and dialogs made white, Harlowe's undo / redo sidebar as a row above the passage.
  Settings changes are posted to the frame (no reload).
- **Pages:** a tap on the left 30 % of the frame (outside links, buttons, form fields and the formats' clickable
  elements) scrolls back a screenful, elsewhere forward (one line of overlap, so no line is cut unread); the page number
  is shown under the frame. `overflow: hidden` is set only once the script runs (class `ik-paged`), which is the
  scrolling fallback. No swipe inside the frame.
- **Menu:** Aa, Restart (reloads the story, keeping its `localStorage` saves, dropping its session), Refresh screen. No
  Save / Restore / Undo / Transcript. Played Twine stories join My adventures; progress records only `lastPlayed`
  (`updateProgress` now takes an optional `turns`).
- **Catalogue:** Twine is now in `scripts/catalog/playability.json`. The sample catalogue gains its Twine game ("Paper
  Lanterns"), played in e2e from a download with the Harlowe fixture; relative links resolve on the IF Archive through
  an injected `<base>`. `looksLikeStory('twine')` wants `<tw-storydata` (Twine 2) or `storeArea` (Twine 1).
- **Fixtures:** `tests/fixtures/twine/lamp-{harlowe,sugarcube}.twee`, built into HTML by
  `scripts/fixtures/build-twine.ts` (a small Twee 3 publisher, tested) with Harlowe 3.3.9 and SugarCube 2.37.3 from the
  Story Format Archive (SHA-256 checked; GitHub releases are not reachable from the dev sandbox, raw files are). The
  script runs at `npm install` (postinstall, after Quixe; formats cached in `vendor/twine/`): the built files (0.5 and
  0.6 MB of minified format code, which CodeQL flagged) are not committed. The formats' licences are. They are served
  at `#/play/fixture-twine-harlowe` and `#/play/fixture-twine-sugarcube`.
- **Not verified here:** WebKit (not installed in the dev sandbox; CI runs it) and a real Kindle (the storage stand-in
  relies on redefining `window.localStorage`, which the Kindle's modern engine should allow; to check in S7.1).
- **Follow-ups:** Twine 1 stories and other formats (Snowman, Chapbook) only get the generic stylesheet; a curated
  allowlist (SPEC §13 risk 5) if real stories misbehave.
