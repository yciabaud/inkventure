## User story

As a Kindle reader on slow Wi-Fi, I want the app to stay light so that it loads quickly; as a maintainer, I want CI to
fail as soon as a change makes an asset too heavy, instead of discovering it at release time.

## Scope

- `size-budget.json` with budgets in KiB: initial JS legacy and modern (gzip), CSS (gzip), fonts as `.woff` and as
  `.woff2`, each lazy JS chunk (gzip), each catalogue shard, and the Kindle first load (legacy JS + CSS + `.woff`).
- `scripts/size/check-size.ts` (run with Node's type stripping): reads the Vite manifest to tell initial chunks from
  lazy ones, measures every file in `dist/`, prints a Markdown table, appends it to the GitHub Actions job summary,
  exits 1 when a budget is exceeded. Pure logic in `scripts/size/budget.ts`.
- `npm run check:size`, run in CI after `check:es5`; added to the pre-push checklist in `CLAUDE.md`.
- Bring the current build within budget.
- Spec and related stories updated: SPEC §10 budgets, cover thumbnails rule (§5.6, S3.1, S3.3), real-device load
  timing in S0.3, S7.1 now only reviews the budgets against device measurements.

## Acceptance criteria

- [x] CI fails when any budget is exceeded, and shows the size table in the job summary.
- [x] The current build passes every budget.
- [x] Lazy chunks and catalogue shards are checked individually as soon as they exist.

## Required tests

**Unit (Vitest)**

- Chunk classification from a manifest (legacy/modern entries, static imports, lazy chunks).
- Budget evaluation: at-budget passes, one byte over fails, each category flagged independently, first load checked
  as a whole, non-JSON files ignored in `catalog/`, Markdown output.

**E2E (Playwright)**

- — (existing suites re-run to confirm the font change doesn't break layout or tap sizes)

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Measuring on a real device (S0.3, S7.1).
- Generating cover thumbnails ourselves (IFDB already serves them).

## Notes & decisions

- **Font trim.** The first run failed on fonts (114.8 KiB `.woff`, 92.7 KiB `.woff2`). Literata italic and
  Source Sans 3 600 were removed; the browser synthesises italic (cover author line) and bold UI text
  (`font-weight: 700`). Result: 70.1 KiB `.woff`, 56.8 KiB `.woff2`.
- **Kindle assumptions.** The Kindle browser was assumed to download the `.woff` fallback, so the Kindle first load
  counts `.woff` files. S0.3 showed the current Kindle fetches **woff2** and the modern bundle (measured first load:
  71 KB encoded), so the budget is conservative; it is kept for older e-readers.
- **First-load budget is 200 KiB**, not 250: with 150 + 20 + 80 = 250 the total could never be the limit that fails.
  Current Kindle first load: 121.6 KiB (legacy JS 49.7 gz + CSS 1.8 gz + fonts 70.1).
- **Units**: KiB (1024 bytes). JS/CSS are measured gzip level 9 (close to what GitHub Pages serves); fonts and
  catalogue shards as stored (fonts are already compressed; shard parse time depends on raw size).
- **Cover images**: IFDB's `coverart?id=…&thumbnail=WxH` (max 250×250) avoids full-size downloads; the rule is in
  SPEC §5.6 and the S3.1 / S3.3 scopes. Images are not in `dist/`, so they are not part of this check.
- Vite now writes `dist/.vite/manifest.json` (`build.manifest: true`); it is only read by the script.
