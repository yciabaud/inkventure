## User story

As a player, I want to play Decker decks (HyperCard-like games of cards and buttons) in the reader, so that this
1-bit, tap-driven kind of game, made for screens like mine, is in Inkventure too.

## Background

The [S0.11 spike](S0.11-decker-spike.md) ran the tour deck on the Kindle with a patched web-decker
([report](../device-reports/2026-10-10-kindle-decker.txt)): ~8.5 s to open, **1.1–1.4 s** from a tap to the new card
(a tick ~450 ms, a draw ~550 ms), no CPU on a still card, and the device keyboard never opens on the canvas. The owner
decided **go** (2026-10-10), with the conditions of the [recommendation](../post-v1-ideas.md#decker): cut the draw,
remove the editor, type with the Kindle's keyboard, card-and-button decks first, under 1 s per tap.

## Scope

- **A Decker reader** like Twine's (S1.9): no `Engine`; the deck runs in `<iframe sandbox="allow-scripts" srcdoc>`
  (opaque origin, no access to the app) inside the usual reader chrome, as its own lazy chunk (`DeckerReader`).
  `engineFor('decker')`, `isAvailable` true on the modern bundle only: Decker is ES2017, so a device on the legacy
  bundle says the game cannot be played there.
- **The runtime**, built from the pinned Decker release by the S0.11 patch script, as an asset the frame loads:
  - the S0.11 patches: loop only while busy, draw only on change, no transitions, frozen animated patterns, steady
    cursor, full width, no corners;
  - **the editor removed** (menus, drawing tools, toolbars, object mode, script editor, property dialogs) and the
    sound code left out, so that it fits the 100 KiB gz lazy-chunk budget (two assets, the Lil interpreter and the UI,
    if one cannot; the budget is not raised);
  - **a faster draw:** convert and put only the rows of the frame buffer that changed (the patched `sync` already
    compares them), and measure what a tick spends to cut what can be cut.
- **Typing:** a tap on an editable field puts a hidden text input over it and focuses it, so that the device keyboard
  opens; what is typed, Backspace and Return go to the Decker field; Decker's drawn keyboard (`keycaps`) is off.
- **Saves:** a deck keeps its state in itself. When the deck goes idle after a change, the frame sends the deck
  (serialized as Decker saves it) to the reader, which keeps it under `save:<tuid>:decker` through `src/storage/`
  (debounced, at most a fixed size: a larger deck plays but does not resume, and the reader says so once). Opening the
  game resumes from it; **Restart** drops it. No Save / Restore / Undo / Transcript (as Twine).
- **Reader chrome:** the top zone shows the deck's name; menu: Aa (only what applies: nothing changes the deck's
  pixels), Restart, Refresh screen, Home / Library. A played deck joins My adventures (`lastPlayed`).
- **Fixture:** the tour deck (MIT, already downloaded for the probe) at `#/play/fixture-decker`.
- SPEC §4.1 (formats), §4.3 (sandbox, now Twine and Decker), §4.4 (saves) and §13 row 12 updated.

## Acceptance criteria

- [ ] The tour deck plays in the reader: a tap on a button changes the card, a field takes typed text from the
      device keyboard, and nothing is drawn on a still card.
- [ ] The deck resumes where it was after a reload; Restart starts it afresh.
- [ ] No lazy chunk or runtime asset over 100 KiB gz; first load unchanged.
- [ ] On the Kindle: a card change under **1 s** from the tap to its first frame, and the deck open in under **5 s**
      (or the Notes give the measured times and what is left, for the owner to decide).
- [ ] Checked on the PR preview and on the Kindle.

## Required tests

**Unit (Vitest)**

- The patch script removes the editor and fails loudly if the upstream code it patches moved.
- The row-diff draw: only changed rows are converted (a frame buffer with one changed row).
- Deck save storage: size cap, Restart clears it.

**E2E (Playwright)**

- `#/play/fixture-decker`: the deck opens in the frame, a tap on a button changes the card, typing into a field
  through the hidden input changes the field, a reload resumes on the same card; the frame cannot reach the app
  (as the Twine sandbox test).

Plus the global gates: lint, `es-check es5` (the runtime asset left out, as in S0.11), size budgets, CI green.

## Out of scope

- Decker games in the catalogue: [S2.9](S2.9-decker-catalogue.md).
- Sound, Decker's `danger` JavaScript bridge (stays off), decks that draw or animate in real time.
