# S6.3 — Ebook download page (desktop)

|---|---|

## User story

As a reader on a computer, I want a page on the Inkventure site where I can download the ebook in my language and
format so that I can copy it to my e-reader.

## Scope

- **Files on the site.** Deployments of `main` build the ebooks (the S6.1 pipeline, from the catalogue being
  deployed) and publish them at stable URLs: `ebook/inkventure-<locale>.epub` and `.azw3`, plus `ebook/books.json`
  (for each file: locale, format, size, build date, commit). No version in the file names, so links shared
  elsewhere keep working. PR previews skip the ebook build: their page says the books are not built for previews.
- **Download page** at `ebook/` (index), a standalone static page like `probe/`, not a route of the app:
  - one block per locale (title, cover thumbnail, short description) with a download button per format: "EPUB"
    (most e-readers) and "AZW3" (Kindle-family e-readers, see the brand-name note below), with file size and build
    date read from `books.json`;
  - short instructions for copying the file to an e-reader: USB cable, the e-reader's own wireless or email transfer
    service (described in generic terms), and opening the book once it is on the device;
  - the page's language follows the browser (EN/FR), with a switch; the user's locale's block comes first;
  - same e-ink design system (black on white, no animations, tap targets ≥ 48 px), and it works on a phone too
    (no horizontal scroll, 16 px gutters).
- **Strings** through i18n: `ebookPage.*` keys in `src/i18n/en.json` and `fr.json` (key parity test). The page is
  generated at build time from those keys (or built as an extra Vite entry that loads the app's i18n module; choose
  one and record it).
- **Links to the page:** from Settings › About in the app (as plain text with the address, since the e-reader itself
  cannot download files easily), from the README, and from the ebook's credits chapter (`{{host}}ebook/`).
- **Size budget:** a new entry per ebook file in `size-budget.json` (proposed: 5 MiB each), agreed with the owner;
  the ebooks are not counted in the app's first-load budget.

## Acceptance criteria

- [ ] After a deployment of `main`, `ebook/` lists the EN and FR books in EPUB and AZW3, and each button downloads a
      file that matches `books.json` (size, date).
- [ ] The page is in the browser's language (EN or FR) with a working switch, and is usable at phone and desktop
      widths.
- [ ] A missing book (failed build, or a preview) shows a clear "not available" message instead of a broken link.
- [ ] SPEC §8 documents the download page and the stable file URLs.

## Required tests

**Unit (Vitest)**

- `books.json` writer: entries, sizes, build date, missing files left out.
- Page model: locale order (browser language first), button labels and sizes, "not available" state.
- i18n key parity (existing test) covers the new keys.

**E2E (Playwright)**

- With stub ebook files and a `books.json` fixture served via `page.route` (no Pandoc or Calibre in e2e): the page
  lists the books, the download links point to the stub files, the language switch works, tap targets ≥ 48 px, no
  horizontal scroll at 360 px wide.
- Without `books.json`: the "not available" message.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Downloading the ebook from the e-reader's browser.
- Store listings (free ebook on stores) and PDF output.
- Final ebook prose (S6.2) and final domain (S7.2): the page uses whatever host and content they produce.

## Notes & decisions

- **Owner's decisions** (2026-10-01, after checking the book on the Kindle: it reads both EPUB and AZW3):
  - the buttons name the **formats** only ("Download EPUB", "Download AZW3"), with a generic hint (most e-readers /
    e-readers that use AZW3); no brand name, and the transfer instructions stay generic;
  - the books are built **in the Deploy workflow**, if it does not make it too long;
  - **no size budget** for the ebooks: the `size-budget.json` entries proposed in the scope are dropped.
- **Deploy workflow:** three jobs. `build` (the app, as before, uploaded as an artifact) and `ebook` (Pandoc,
  EPUBCheck, Calibre in the Playwright image, from the same published catalogue) run in parallel; `publish` puts the
  books in `dist/ebook/` and deploys. The ebook build took ~2 min in the Ebook workflow and the deploy ~50 s, so a
  deployment should take ~2.5–3 min instead of ~1 min. If the ebook job fails, the site is published without books
  (the page says they are not available; the previous ones are removed, so nothing stale is served).
- **Page built at build time, not as a Vite entry:** a second Vite entry would be counted in the app's initial-JS
  budgets (`scripts/size/budget.ts` treats every entry as initial). `scripts/build/ebook-page.ts` (Vite plugin)
  writes `ebook/index.html` with the `ebookPage.*` strings of every locale inlined, and `ebook/page.js`:
  `src/ebook-page/page.ts` (self-contained, unit tested) compiled to ES5 with TypeScript's `transpileModule`, checked
  by `npm run check:es5`. The page reads `books.json` with XHR; not served by `npm run dev`.
- **Language:** `?lang=en|fr` in the address, else the browser's languages, else English; no persistence (it is not
  the app, so no `src/storage/`). Language names in their own language.
- **Covers:** the build also renders the book cover at 240 px wide (`inkventure-<locale>-cover.jpg`, ~12 KB) for the
  page; `books.json` lists them under `covers`.
- **Description** of each edition: one shared `ebookPage.description` string in the page's language.
- **Links:** Settings › About ends with a paragraph giving the page's address (computed from the app's own address)
  as text; the README links to it; both credits chapters end with `<{{host}}ebook/>`.
- PR previews never build the books: their page shows the "not available" message.
