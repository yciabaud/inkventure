## User story

As the owner, I want the first-load budget to measure what the baseline Kindle really downloads, so that the budget
guards the device it is meant for, and stories are not blocked by a number about another device.

## Background

Found on 2026-10-03 after [S1.17](S1.17-contextual-answer-chips.md), which brought "First load (Kindle)" to
199.8 KiB of its 200 KiB budget. That line was written in S0.7, before the Kindle was measured, and assumes it loads
the **legacy** (ES5) bundle and the **.woff** fonts. S0.3 measured the opposite (SPEC §2.2, `docs/device-reports/`:
`app.bundle: modern (ES modules)`, `app.fontFormat: woff2 x3`).

| What the line counted (2026-10-03) | KiB gz |
|---|---:|
| Legacy JS: polyfills (core-js + SystemJS) | 62.4 |
| Legacy JS: the app, transpiled to ES5 | 62.3 |
| CSS | 5.0 |
| Fonts, .woff | 70.1 |
| **Total** | **199.8** |

What the measured Kindle loads: modern JS 56.6 + CSS 5.0 + woff2 56.8 ≈ **118.4 KiB**. In the modern JS (estimated
from source maps): the reader ≈ 18, the EN **and** FR dictionaries ≈ 9–11 (both always loaded), the Library ≈ 6,
Preact 4.7, Home / game page / settings ≈ 5, and a **test fixture** inlined in the production bundle
(`tests/fixtures/ink/lamp.json`, base64, 1.3).

## Scope

- **Measure:** "First load (Kindle)" counts the modern JS + CSS + .woff2 (what S0.3 measured), with the same 200 KiB
  budget (new key `firstLoad`). The legacy load (legacy JS + CSS + .woff) keeps its own line and its 200 KiB budget
  (`firstLoadLegacy`), named for the old e-readers it serves (best effort, SPEC §2.2). Row labels say which device
  each line is for. The owner agreed to this change of measure on 2026-10-03.
- **Slim the bundle:**
  - the test fixtures are never inlined in the production bundle (they become separate files, fetched only by the
    fixture routes);
  - only the active language's dictionary is loaded: English stays in the bundle (default and fallback), French
    becomes a lazy chunk loaded before the first render when the UI is in French, and when the user switches to it.
- SPEC §10 (budgets) updated.

## Acceptance criteria

- [x] `npm run check:size` shows "First load (Kindle: modern JS + CSS + .woff2)" and "First load (old e-readers:
      legacy JS + CSS + .woff)", each against its budget; CI fails if either is over.
- [x] The production bundle has no test fixture inlined; the fixture routes still play.
- [x] An English UI loads no French dictionary; a French UI (browser language or the setting) shows French from the
      first render; switching language in Settings works both ways. _e2e: `i18n.spec.ts` (no `fr-*.js` request in
      English, the first heading already French), `settings-screen.spec.ts` (both ways)._
- [x] Both first loads are smaller than before this story. _Kindle 118.4 → 111.9 KiB; old e-readers 199.8 → 193.3
      KiB (see Notes)._

## Required tests

**Unit (Vitest)**

- Budget evaluation: the two first-load rows, their files and budgets.
- i18n: French loads on demand; `setLocale('fr')` applies once it is loaded; English needs no load.

**E2E (Playwright)**

- A French browser shows French on Home at once; switching to English and back in Settings works (existing i18n
  tests, kept green). The fixture games still load.

Plus the global gates: lint, `es-check es5` on the legacy bundle, size budgets, CI green.

## Out of scope

- Loading the reader screen on demand (≈ 18 KiB off the first load): a later story if the budget tightens again.
- Raising any budget.

## Notes & decisions

- **Legacy targets are not a lever.** Measured on 2026-10-03: the polyfills chunk is 62.4 KiB gz with today's targets
  (`defaults`, `safari >= 5`, `ie >= 11`), 62.0 without IE 11, 61.7 for Safari ≥ 7, 59.0 for Safari ≥ 9. Old WebKit
  needs them; dropping it would drop the old e-readers. Targets unchanged.
- **Results** (2026-10-03, after S1.17):

  | | Before | After |
  |---|---:|---:|
  | Kindle (modern JS + CSS + .woff2) | 118.4 | **111.9** (+ 5.9 for the French chunk) |
  | Old e-readers (legacy JS + CSS + .woff) | 199.8 | **193.3** |
  | Initial JS, modern | 56.6 | 50.2 |
  | Initial JS, legacy | 124.7 | 118.3 |

  (KiB gz.) The fixtures saved 1.8 KiB (modern) and 1.7 (legacy); the French dictionary 4.6 in each bundle.
- **Fixtures:** imported with `?url&no-inline` (`ReaderScreen.tsx`): only `lamp.json` (2.5 KB) was small enough to be
  inlined as base64, but all six use the same suffix so none can come back into the bundle.
- **Dictionaries — why English stays in the bundle:** it is the default and the fallback for a missing key, and every
  module calls `t()` synchronously. Loading both on demand would make every first render wait for a request. With
  English bundled: an English UI downloads no French; a French UI downloads the same bytes as before, in one extra
  request (the chunk is 5.9 KiB gz) made before the first render (`localeReady()` in `main.tsx`). If it fails
  (offline), the app renders in English. `setLocale` applies a locale once its dictionary is loaded, and ignores a load
  that finishes after another choice.
- **Kindle check:** the first render in French should look the same; Home's time is shown by the probe's app line or
  `?perf=1`. To compare on the device.
