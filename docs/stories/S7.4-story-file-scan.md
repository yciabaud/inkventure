## User story

As the owner, I want to know which games of the whole catalogue use a display feature the reader drops, read from
their story files without playing them, so that the rendering survey replays the games that matter and the backlog
follows how often each problem happens.

## Background

Raised by the owner on 2026-10-04, after S7.3. The rendering survey plays a few commands of 60 games: later scenes and
the rest of the catalogue (about 2,000 parser games) are not seen. Games' source code is rarely published, but their
story file is the compiled program the engine runs, and it can be read without playing it:

- **Z-machine:** the routines can be disassembled; the opcodes that matter for display are known (`split_window`,
  `set_window`, `set_text_style` with reverse video, `set_font`, `set_colour`, `read_char` with a time and a routine,
  `sound_effect`, `print_unicode`, `erase_window`, `output_stream`; `draw_picture` in version 6).
- **Glulx:** every display call goes through the `glk` opcode with a function number, usually a constant: window
  opening and its type (graphics, text grid), timers, hyperlinks, sound channels, images, style hints.
- **Text:** the game's strings can be decoded (Z-machine abbreviations and Unicode table; Glulx string table), which
  lists every character the game can print, not only those of its first turns.

What a file **can** do is not what the player sees: every Inform game has the code of its status line, and libraries
include menu or quote-box routines a game may never call. Signals must be chosen so as to mean something (a timer
requested, a graphics window opened, reverse video on more than the status line), and the survey (S7.3) confirms what
the player sees by replaying the games the scan points to (`--only`).

## Scope

- A script (`scripts/survey/scan.ts`, `npm run survey:scan`, by hand, never in CI) that reads every parser game's story
  file of the published catalogue (Blorb or not, zipped or not; downloaded at 1 request per second, sharing the
  survey's cache in `data/cache/survey/`):
  - a Z-machine disassembler (versions 3, 5, 8; others reported, not scanned) walking the routines from the start and
    every packed address found, counting the display opcodes and their operand forms that matter;
  - a Glulx scan of the functions for the `glk` opcode with a constant selector, counting the Glk calls that matter
    (and the window types passed to `glk_window_open` when constant);
  - a string decoder for both formats, listing the characters outside the bundled fonts' latin subset (shared with
    `scripts/survey/detect.ts`);
  - a time limit per file; a file that fails is reported, never stops the run.
- A report `docs/reports/story-file-scan-<date>.md`: per feature, the number of games that use it and the list (featured
  and most-rated first); per game, its features; the list of games for the survey to replay
  (`npm run survey:rendering -- --only …`), with the command line written out.
- The first report, its analysis, and the follow-up stories proposed to the owner.

## Acceptance criteria

- [x] `npm run survey:scan` reads the catalogue's parser games and writes the report; a failure is reported per game.
- [x] Each feature listed above is detected on the fixtures and on recorded samples of real games (unit tests).
- [x] The first report is committed, the survey rerun on the games it points to, and the follow-up stories proposed.

## Required tests

**Unit (Vitest)**

- Z-machine: the disassembler on the fixtures (`lamp.z5`, `clock.z5`): routines found, display opcodes counted (the
  fixture's GUIDE menu, its status windows, `read_char`), strings decoded.
- Glulx: the scan on the Glulx fixture (`lamp.ulx`): Glk selectors counted, window types.
- The report from fake results.

No e2e test: the script does not touch the app's UI. Plus the global gates: lint, `es-check es5` on the legacy bundle
(unchanged), size budgets (unchanged), CI green.

## Out of scope

- Fixing what the scan finds (follow-up stories).
- TADS, Hugo, ADRIFT and other formats the app does not play; Twine and ink (no Glk windows).
- A full decompiler: only what the display features need.

## Notes & decisions

- **First reports:** [story-file-scan-2026-10-04.md](../reports/story-file-scan-2026-10-04.md) (2,104 parser games,
  2,055 read) and the replay of the 32 games it points to,
  [rendering-survey-2026-10-04.md](../reports/rendering-survey-2026-10-04.md). The analysis and the proposed follow-ups
  are at the top of the scan report: quote boxes in 266 games (S1.23, to widen to any tall upper window), real time in
  116 games, a crash of Z-machine games on a cancelled restore prompt (an app bug the replay found), 47 catalogue entries
  that do not open plus 8 version 6 games, hyperlinks in 25 games.
- **Z-machine** (`scripts/survey/zcode.ts`): compilers lay the routines out one after the other from the start of high
  memory, each on a packed address, then the strings. The code is read straight through, as txd does: a routine ends
  after an instruction that stops the flow past every branch target; code after a return that nothing reaches is read as
  part of the routine; where the sweep cannot read on, it starts again at the next routine a call names, and routines
  named by calls but stepped over are decoded on their own. Each instruction is checked (opcode for the version, number
  of operands), which refuses data read as code. On the fixtures and real games, every routine a constant call names is
  found.
- **Glulx** (`scripts/survey/glulx.ts`): the ROM is read straight through: functions (0xC0/0xC1, their instructions up to
  the next object; Inform never emits 4-byte opcodes), Unicode strings (only when every character is a real one), and
  compressed strings walked through the decoding table's Huffman tree to find their end; the characters the game can
  print are those of the decoding table's nodes and of the literal strings.
- **Glk calls:** the libraries call Glk through one-line wrappers (`glk_window_open` → `@glk 35`): the wrappers are
  found, then their call sites, whose arguments are the constants pushed just before (`window_open`'s window type and
  rock). The Inform libraries' windows are told by their rocks (201 main, 202 status, 203 quotation).
- **Library code:** every Inform game holds the library's status line, menus and keyboard routines, so their opcodes
  say nothing about the game. A routine's fingerprint (its opcodes and operand kinds, without addresses) found in at
  least 1 % of the games of its format (and 3) is library code and is left out; so are characters printed by that many
  games (the runtime messages of a compiler's library, ∞ and ⚠ in Inform 7's). Windows the libraries never open
  (graphics windows, grids and buffers with other rocks), quote boxes and version 6 count wherever they are.
- **Quote boxes:** Inform compiles `box` to a call to a veneer routine (Z-machine: one that splits the window, moves the
  cursor, sets reverse video and turns buffering off, which the status line does not; Glulx: the library's routine
  that opens the quotation window, rock 203); the calls to it are counted. The lamp fixtures (Z-machine and Glulx) get
  a QUOTE command with a `box`, for these tests and for S1.23.
- **The scan reads the zips as the app does** (`extractPrimary`: the file of that name, whatever its folder), so its
  "not read" list is the games the app cannot open either.
- **The rendering survey (S7.3) got two fixes:** an error thrown outside the engine's callbacks (a vendor library's
  timer) stops that game, not the run; and an error while playing is reported as an engine error, not as a download
  failure. Its catalogue and download code moved to `scripts/survey/catalog.ts`, shared with the scan.
- **Limits:** a constant argument is needed to know a window's type or a timer's interval (the replays found graphics
  windows the scan could not see); a library extension used by more than 1 % of the games counts as library code; the
  Z-machine's reverse video is not read (the status line uses it in every game).
