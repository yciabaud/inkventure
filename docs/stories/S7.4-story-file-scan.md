## User story

As the owner, I want to know which games of the whole catalogue use a display feature the reader drops, read from
their story files without playing them, so that the rendering survey replays the games that matter and the backlog
follows how often each problem happens.

## Background

Raised by the owner on 2026-10-04, after S7.3. The rendering survey plays a few commands of 60 games: later scenes and
the rest of the catalogue (about 2,000 parser games) are not seen. Games' source code is rarely published, but their
story file is the compiled program the engine runs, and it can be read without playing it:

- **Z-machine:** the routines can be disassembled; the opcodes that matter for display are known (`split_window`,
  `set_window`, `set_text_style` with reverse video, `set_font`, `set_colour`, `read_char` with a time and a routine,
  `sound_effect`, `print_unicode`, `erase_window`, `output_stream`; `draw_picture` in version 6).
- **Glulx:** every display call goes through the `glk` opcode with a function number, usually a constant: window
  opening and its type (graphics, text grid), timers, hyperlinks, sound channels, images, style hints.
- **Text:** the game's strings can be decoded (Z-machine abbreviations and Unicode table; Glulx string table), which
  lists every character the game can print, not only those of its first turns.

What a file **can** do is not what the player sees: every Inform game has the code of its status line, and libraries
include menu or quote-box routines a game may never call. Signals must be chosen so as to mean something (a timer
requested, a graphics window opened, reverse video on more than the status line), and the survey (S7.3) confirms what
the player sees by replaying the games the scan points to (`--only`).

## Scope

- A script (`scripts/survey/scan.ts`, `npm run survey:scan`, by hand, never in CI) that reads every parser game's story
  file of the published catalogue (Blorb or not, zipped or not; downloaded at 1 request per second, sharing the
  survey's cache in `data/cache/survey/`):
  - a Z-machine disassembler (versions 3, 5, 8; others reported, not scanned) walking the routines from the start and
    every packed address found, counting the display opcodes and their operand forms that matter;
  - a Glulx scan of the functions for the `glk` opcode with a constant selector, counting the Glk calls that matter
    (and the window types passed to `glk_window_open` when constant);
  - a string decoder for both formats, listing the characters outside the bundled fonts' latin subset (shared with
    `scripts/survey/detect.ts`);
  - a time limit per file; a file that fails is reported, never stops the run.
- A report `docs/reports/story-file-scan-<date>.md`: per feature, the number of games that use it and the list (featured
  and most-rated first); per game, its features; the list of games for the survey to replay
  (`npm run survey:rendering -- --only …`), with the command line written out.
- The first report, its analysis, and the follow-up stories proposed to the owner.

## Acceptance criteria

- [ ] `npm run survey:scan` reads the catalogue's parser games and writes the report; a failure is reported per game.
- [ ] Each feature listed above is detected on the fixtures and on recorded samples of real games (unit tests).
- [ ] The first report is committed, the survey rerun on the games it points to, and the follow-up stories proposed.

## Required tests

**Unit (Vitest)**

- Z-machine: the disassembler on the fixtures (`lamp.z5`, `clock.z5`): routines found, display opcodes counted (the
  fixture's GUIDE menu, its status windows, `read_char`), strings decoded.
- Glulx: the scan on the Glulx fixture (`lamp.ulx`): Glk selectors counted, window types.
- The report from fake results.

No e2e test: the script does not touch the app's UI. Plus the global gates: lint, `es-check es5` on the legacy bundle
(unchanged), size budgets (unchanged), CI green.

## Out of scope

- Fixing what the scan finds (follow-up stories).
- TADS, Hugo, ADRIFT and other formats the app does not play; Twine and ink (no Glk windows).
- A full decompiler: only what the display features need.
