## User story

As a first-time visitor, I want a welcoming home with recommended games so that I can start playing immediately.

## Scope

- Featured shelf from `catalog/featured.json` (the list of the UI locale, SPEC §5.3) with pitch in UI language when
  curated, starter badge, horizontal paging with ‹ › buttons.
- Leave out the games already in progress (progress record or in *My adventures*); the list is longer than a shelf
  for that reason. Only games in the UI language are listed.
- First-launch empty state: welcome text, "How to play" help page, Featured first.

## Acceptance criteria

- [x] Home shows the featured games with localized pitches; tapping one opens its detail page.

## Required tests

**Unit (Vitest)**

- Shelf paging logic.
- Featured filtering: games in progress left out, order kept.

**E2E (Playwright)**

- Fresh profile: welcome + featured shelf visible; tap a card → detail.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- My adventures (S4.2).

## Notes & decisions

- **Code**: `src/catalog/featured.ts` (`loadFeatured`, `featuredFor`: the UI locale's list in order without the
  games in progress, at most 24; `shelfLayout`), `inProgressTuids` in `src/storage/home.ts` (progress record,
  autosave or My adventures), `HomeScreen.tsx`, `HelpScreen.tsx` (`#/help`), `src/ui/PagedParagraphs.tsx` (the
  paged text of S3.3, shared with the help page).
- **Cards**: cover, "Start here" badge for curated starters, title, then the pitch (curated games) or the author
  (best-rated games). Tapping one opens its detail page. Paged with ‹ › buttons (no history entry), as many cards as
  fit; the covers are sized to the height left under the welcome, so the page never scrolls, from a phone to the
  large e-reader. The pager has its own slot so that showing it does not change the room measured for the cards.
- **First launch** = no game started nor added to Home: welcome text and "How to play". The test adventure link moved
  from Home to the help page ("try it"). "Browse the library" only shows when there is no shelf (no list for the
  language, or `featured.json` failed to load): the top bar already has Library.
- **Paged text fix** (found here, latent in S3.3): the text area shrank when its pager appeared, and was measured one
  render late, so a text close to one page could make the page count and the pager flip forever (the page froze).
  The area now holds the text and the pager and is measured as a whole; the text gets the full height, or the height
  above the pager once it is known not to fit.
- **Tests**: unit `featured.test.ts` (filtering and order, max, locale without a list, shelf layout, loading and
  version check), `home.test.ts` (games in progress), router (`#/help`). E2E `home.spec.ts`: fresh profile welcome +
  shelf with pitch and badge, card → detail; games in progress left out; French shelf and pitch; paging a long
  shelf; the help page. `smoke.spec.ts` serves a blank image for IFDB covers (the shelf shows some on Home).
- **Games that could not load** (owner's test of the preview: Le butin du Capitaine Verdeterre, Life On Mars?): their
  only file is on the author's site, which does not let a browser page read it (no CORS); 207 of the 1,693 games were
  in that case (6 of the 16 French ones). Decided with the owner: check it at crawl time. `check-cors.ts` (weekly
  workflow step) requests each file outside the IF Archive as the app would and caches the result for 30 days on the
  `catalog` branch; the resolver then drops the games it cannot read (`unreadable-host`). The two games left the
  Featured selection. The published catalogue changes at the next Catalogue run (run it by hand after merging).
  Mirroring the files whose licence allows it (SPEC §5.5 fallback 2) was discussed and **postponed** by the owner:
  IFDB's JSON API has no licence field, and "Freeware" does not grant redistribution. To reconsider if games are missed.
- **Follow-ups**: other e2e specs that open Home or the Library still let the browser request IFDB cover thumbnails
  (they fail without network, harmlessly); a shared fixture blocking `ifdb.org` would make every spec explicit.
