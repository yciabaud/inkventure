## User story

As a player, I want to find Decker games in the Library and on Home, so that I can play them like the other games.

## Background

The IF Archive's master index (2026-10-10) lists **about 15 Decker games**, each a zip of Decker's web export (an
HTML page with the deck in a `<script language="decker">` block): Naarel's games in `games/html/` (Black Coffee, the
Alchemist's Oath trilogy, te/ra/to/ma, salting wounds…), the Neo-Twiny Jam 2024 entries (The Ocean View from the Keiyo
Line, Ontological Mystery, peelings, Whether), SPILL YOUR GUT (Barebones 2024), and Decker games inside competition
zips. IFDB lists Decker games as web games (`hypertextgame`, development system "Decker"). Ink web exports (S2.7) are
found the same way: a known runtime's page, inside a zip on the IF Archive.

## Scope

- **Pipeline** (`scripts/catalog/`, cached, 1 request per second, like the ink and story checks): a game whose IFDB
  record names Decker (development system, format or tags), or whose IF Archive zip holds a page with a
  `<script language="decker">` block, gets format `decker` when the deck can be extracted and opens (it parses, its
  version is one the runtime reads). The file is the zip (or page) and the path of the page in it, as for Twine zips.
- **App:** the game loader extracts the deck from the page (the block's text) and hands it to the Decker reader
  (S1.29); `looksLikeStory('decker')` checks for the block.
- **Library:** Decker in the format filter and badge (`formatName`), i18n EN/FR.
- **Suitability:** decks that need real-time drawing or animation play badly on e-ink. Record per game what a static
  look at the deck shows (animated widgets, `sleep` loops, canvases drawn by scripts) in the run's summary; games the
  owner checks on the Kindle and finds unplayable go to the exclude list.
- The sample catalogue gains a Decker game (the tour deck as a web export fixture), played in e2e from a download.
- SPEC §4.1 and §5.2 updated.

## Acceptance criteria

- [ ] The Decker games of the IF Archive with an IFDB record are in the catalogue with format `decker`, or in the
      run's summary with the reason they are not.
- [ ] A catalogue Decker game downloads, opens in the Decker reader and plays (e2e with a recorded fixture).
- [ ] Decker shows in the Library's format filter and on the game page.
- [ ] A Decker game from the catalogue checked on the Kindle.

## Required tests

**Unit (Vitest)**

- Deck extraction from a web export page (block found, none, two pages in a zip).
- The pipeline check: a zip with a deck, a zip without, a deck that does not parse (recorded fixtures, no network).

**E2E (Playwright)**

- The sample catalogue's Decker game: Library filter, game page, download, the first card shown.

Plus the global gates.

## Out of scope

- Decker games hosted only on itch.io (no IF Archive file): see the catalogue strategy in
  [post-v1-ideas.md](../post-v1-ideas.md).
- Bitsy and the other formats.

## Notes & decisions

- **Real data (2026-10-10):** IFDB lists 67 games made with Decker, 39 with a download link. 24 are only on itch.io
  (dropped as `unsupported-format`, as other game-store pages). The IF Archive holds 15: **13 decks kept**; *SPILL YOUR
  GUT* is three decks linked from a page (`no-deck`: "3 decks"), and *in eyes of men, in face of God* has a broken
  IFDB link (HTTP 404). All 13 open in the reader with the app's runtime (Decker 1.71 reads decks saved by 1.32–1.58).
- **Pipeline:** query `downloadable:yes system:decker`; `linkFormat` gives `decker` (`deckerExport`) to a zip whose
  named file is a page, or a page outside itch.io, of a game whose development system names Decker, before the Twine
  and ink rules (the check decides: no deck, no game). `check-decker.ts` (`scripts/catalog/decker.ts`) opens each
  export once and caches the page holding the deck in `cache/decker.json` (90 days), with notes (cards, size, animated
  widgets, `sleep` calls, canvases, sounds) listed in the job summary; `resolve.ts --decker` points the game at that
  page and drops the others (`no-deck`). "The deck parses" is checked as Decker's text format, version 1: running Lil
  in the pipeline would be a second runtime to keep; the reader shows an error page when a deck does not open.
- **App:** after the download, the deck is taken out of the page (`deckerDeck` in `storyFile.ts`) and only the deck is
  cached or kept offline; `PlayScreen` opens it in the Decker reader. A catalogue game is named by its catalogue title
  (decks are often named after their file, e.g. `inheatofflamesinwaterscold.deck`); the tour deck keeps its own name.
  Library: "Decker" in the format filter (from the facets) and on the game page, with the "Experimental" badge.
- **Suitability (first look):** most decks are cards and buttons. To check on the Kindle first: *Violent Delight*
  (52 animated widgets, `sleep`), *EyeOS* (9.3 MB deck, 18 canvases, 50 sounds), *Ontological Mystery* (animated
  widgets, canvases), *Whether* (3.8 MB deck), *NIEZWYCIĘŻONA* (3 MB). Decks over 1 M characters play but do not resume
  (S1.29's save cap).
- **Sample catalogue:** "The Decker Tour" (`fxdeck0000000012`), the tour deck as a zipped web export
  (`tests/fixtures/decker/tour.zip`, built at install), played in `tests/e2e/decker-catalog.spec.ts`.
- **Owner's first test, on a phone (preview):** *Black Coffee* went black after a while, *Ontological Mystery* played
  sound, and *EyeOS*'s search field opened no keyboard. Fixed in the runtime (`decker-runtime.ts`): the card is drawn
  whole again when the page is shown again (`visibilitychange`, `pageshow`, a canvas's `contextrestored`: Chrome on
  Android may drop a hidden page's canvas pixels, and the reader draws only what changes); sound stays (the owner is
  fine with it on a phone) but `play` does nothing where the browser has no Web Audio, instead of stopping the deck
  with an error (upstream assumes it; the worry was the Kindle); the hidden input also finds editable fields inside
  contraptions (EyeOS's search box is one); a screen narrower than the card at one device pixel per deck pixel gets
  the fractional zoom that fits. *Black Coffee*'s last card is black with a mug and no button: its ending. Animated
  widgets still animate, slowed to 4 frames a second (S0.11's loop).
- **Summary:** the ink games' line became a per-system one (`**Ink games**`, `**Decker games**`).
