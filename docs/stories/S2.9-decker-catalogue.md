## User story

As a player, I want to find Decker games in the Library and on Home, so that I can play them like the other games.

## Background

The IF Archive's master index (2026-10-10) lists **about 15 Decker games**, each a zip of Decker's web export (an
HTML page with the deck in a `<script language="decker">` block): Naarel's games in `games/html/` (Black Coffee, the
Alchemist's Oath trilogy, te/ra/to/ma, salting wounds…), the Neo-Twiny Jam 2024 entries (The Ocean View from the Keiyo
Line, Ontological Mystery, peelings, Whether), SPILL YOUR GUT (Barebones 2024), and Decker games inside competition
zips. IFDB lists Decker games as web games (`hypertextgame`, development system "Decker"). Ink web exports (S2.7) are
found the same way: a known runtime's page, inside a zip on the IF Archive.

## Scope

- **Pipeline** (`scripts/catalog/`, cached, 1 request per second, like the ink and story checks): a game whose IFDB
  record names Decker (development system, format or tags), or whose IF Archive zip holds a page with a
  `<script language="decker">` block, gets format `decker` when the deck can be extracted and opens (it parses, its
  version is one the runtime reads). The file is the zip (or page) and the path of the page in it, as for Twine zips.
- **App:** the game loader extracts the deck from the page (the block's text) and hands it to the Decker reader
  (S1.29); `looksLikeStory('decker')` checks for the block.
- **Library:** Decker in the format filter and badge (`formatName`), i18n EN/FR.
- **Suitability:** decks that need real-time drawing or animation play badly on e-ink. Record per game what a static
  look at the deck shows (animated widgets, `sleep` loops, canvases drawn by scripts) in the run's summary; games the
  owner checks on the Kindle and finds unplayable go to the exclude list.
- The sample catalogue gains a Decker game (the tour deck as a web export fixture), played in e2e from a download.
- SPEC §4.1 and §5.2 updated.

## Acceptance criteria

- [ ] The Decker games of the IF Archive with an IFDB record are in the catalogue with format `decker`, or in the
      run's summary with the reason they are not.
- [ ] A catalogue Decker game downloads, opens in the Decker reader and plays (e2e with a recorded fixture).
- [ ] Decker shows in the Library's format filter and on the game page.
- [ ] A Decker game from the catalogue checked on the Kindle.

## Required tests

**Unit (Vitest)**

- Deck extraction from a web export page (block found, none, two pages in a zip).
- The pipeline check: a zip with a deck, a zip without, a deck that does not parse (recorded fixtures, no network).

**E2E (Playwright)**

- The sample catalogue's Decker game: Library filter, game page, download, the first card shown.

Plus the global gates.

## Out of scope

- Decker games hosted only on itch.io (no IF Archive file): see the catalogue strategy in
  [post-v1-ideas.md](../post-v1-ideas.md).
- Bitsy and the other formats.
