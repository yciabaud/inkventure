## User story

As a reader, I want to filter by genre, language, format, rating, length, forgiveness and year so that I find my next adventure.

## Scope

- Filters panel with the facets of SPEC §3.4 (values from `meta.json`, with counts).
- Sort options: best rated, most rated, newest, title.
- "Start here" filter (featured starter or tag).
- Filters and sort serialised in the hash; "Clear filters".

## Acceptance criteria

- [x] Every filter narrows results correctly and combinations work; state survives reload and back button.

## Required tests

**Unit (Vitest)**

- Filter predicates, combination logic, sort comparators, hash serialisation.

**E2E (Playwright)**

- Select French + Z-machine + ★4+, verify results and count; reload keeps filters.

Plus the global gates: lint, `es-check es5` on the legacy bundle, CI green.

## Out of scope

- Saved searches.

## Notes & decisions

- **Code**: `src/catalog/filters.ts` (pure: hash parsing and serialisation, predicates, sort comparators, facet
  options, language names), `src/screens/library/FiltersPanel.tsx`, `LibraryScreen.tsx` (search → filters → sort,
  memoised), `useArea.ts` (the list measuring hook, now shared). SPEC §3.4 and §5.2 updated.
- **Panel instead of a dialog**: a dialog cannot hold ten filters and a hundred genres on 600 × 800 without
  scrolling, so the panel replaces the results (`panel` in the hash): a first page with the sort and one row per
  filter showing its value, then a page of choices per filter (counts shown), as many 56 px rows as fit, paged with
  ‹ › buttons (`Pager` gained an `onPage` variant that adds no history entry). After editing a filter the first page
  reopens on that filter's row (short screens page it). The Year page has two number fields and Apply.
- **History**: the "Filters" link adds one history entry; every choice then *replaces* it, and "Show n adventures"
  replaces it with the results. So back from the results goes to the unfiltered results, and back while the panel is
  open leaves it as the results were (a cancel). A single choice (sort, rating, number of ratings, "Any") returns to
  the first page; multi-select pages stay open.
- **Semantics**: OR within a filter, AND across filters; a game with an unknown value is left out by a filter on
  it (only 182 of the 1,693 real games have a play time). Genre spellings differing only by case are merged
  ("Science Fiction"/"Science fiction"), keeping the most frequent one. Counts are the catalogue-wide counts of
  `meta.json` (and of the rows for the fixed choices), not recomputed for the other filters.
- **Sort**: best rated is the default (the most useful way to browse 1,700 games); with a query, ties keep the search
  order (title matches first). The tie-break is explicit: older WebKit's `Array#sort` is not stable.
- **"Start here"**: the index gains `st: 1` for games carrying an IFDB tag of `scripts/catalog/starter-tags.json`
  (*recommended for beginners*, *good for beginners*…, 14 games in the current crawl; *easy* and *introcomp* are
  left out as not about newcomers). The loader then reads `featured.json` and flags its starters (curated `starter`
  games), so the filter works before the next catalogue run too. Featured rows now take `st` from the index row as
  well, so a tagged best-rated game gets the Home "Start here" badge (SPEC §3.3).
- **Forgiveness**: IFDB's JSON API still has no forgiveness (S2.2), so the filter is implemented (`fg` in the row
  type and schema) but only shown once some row carries it. Follow-up: fetch it (iFiction XML) in the pipeline.
- **Size**: +5 KiB gzip on the legacy bundle (Kindle first load 170 / 200 KiB).
- **Tests**: unit `src/catalog/filters.test.ts` (predicates, combinations, sorts, stability, hash round trip,
  malformed values, genre merging), loader (starters from `featured.json`), emitter (`st`), Pager buttons. E2E
  `library-filters.spec.ts` (30 synthetic games): French + Z-code + ★ 4+ gives the 3 expected games best rated first,
  survives reload, a game and back, and back to the unfiltered results; sort by newest, "Start here", a year range,
  search within filters, clearing the filters; the panel does not scroll.
