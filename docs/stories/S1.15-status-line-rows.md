## User story

As a player of a parser game, I want to see every line the game writes in its status window, so that I don't
lose its progress counters, its map hints or a menu's instructions.

## Background

Found on 2026-10-01 (featured games, production vs Parchment). The engines send the whole status window
(`status` block, one string per row), but the reader shows only the first row (`splitStatus` in
`src/engines/transcript.ts` reads `status[0]`).

- **Bronze** (`9p8kh3im2j9h2881`): Parchment shows three rows, "Drawbridge / Great Outdoors / Rooms searched: 0/55",
  plus a compass of exits on the right. Inkventure shows "Drawbridge N": the region and the progress counter are
  lost.
- **Inform menus** (Bronze `HELP`, and any game using the Menus extension): rows 2–3 hold the legend
  "N = Next / P = Previous / Q = Quit Menu / ENTER = Select". It is not shown, so the player cannot know which keys
  work ([S1.12](S1.12-single-key-prompts.md) makes chips from it, once the rows reach the reader).
- Inform's quote boxes (`box`) are drawn in the upper window too.

## Scope

- The top zone shows every non-empty row of the status window, each one split into left and right parts like row 1
  (location / score), in the UI font. Blank rows are dropped. Past a cap (e.g. 4 rows; choose and record it), the
  rest can be read in the reader menu (⋯) and the top zone ends with "…".
- The text area gets shorter by the zone's height: when the number of rows changes, re-paginate, keeping the reading
  position (as for a settings change). The page height of earlier pages follows SPEC §3.6 (shared text-area
  height): record how.
- The key-chip extraction of [S1.12](S1.12-single-key-prompts.md) reads every row (if S1.12 is done first, check it).
- Ink and Twine unchanged.
- SPEC §3.6 "Status line" updated.

## Notes & decisions

- **Cap: 4 lines in the top zone.** Up to 4 non-empty rows show; past that, the first 3 and a "…" line, and the reader
  menu (⋯) lists every row under its actions ("Status window" group). The menu now opens under the top zone, whatever
  its height (it was placed at a fixed 50 px).
- Row 1 keeps the bold location; later rows are in the regular weight. Each row is split like row 1 (two spaces or more
  between a left and a right part), so a compass of exits ends on the right, as text. Runs of spaces inside a part
  collapse in HTML ("W  OUT" reads "W OUT"), as they already did for "Score: 0  Moves: 2".
- **Page height (SPEC §3.6, one text-area height):** all pages share the current height. When the number of rows
  changes, every page is laid out again with the new height, keeping the reading position. New text and new rows
  usually come in the same update, which is laid out after the DOM is drawn (so with the new height); a change of rows
  alone is caught by a `frameKey` on `PagedText` (row count), as e-readers may lack `ResizeObserver`. Checked in e2e
  with `ResizeObserver` removed as well.
- The key chips of [S1.12](S1.12-single-key-prompts.md) already read every status row (`findKeys(texts, status)`):
  nothing to change once the rows reach the reader.
- Fixture: `tests/fixtures/zmachine/lamp.inf` replaces `DrawStatusLine` (the library's location / score / moves row) and
  draws two more rows inside the shed ("Saltmere Rock" with "W  OUT" on the right, "Sheds searched: 1/1"); rebuilt
  with Inform 6.41 (`scripts/fixtures/build-z.sh`).
- `splitStatus` (row 1) stays for the location used by saves and noun chips; `statusRows` gives the displayed rows.

  screens piling up ([S1.16](S1.16-cleared-screens-and-menus.md)), and a tappable compass
