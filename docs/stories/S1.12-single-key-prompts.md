## User story

As a player on an e-reader with no physical keyboard, I want to send the key a game asks for ("press N",
"choose 1 or 2", a menu's N / P / Q), so that I can start these games and leave their menus.

## Background

Found on 2026-10-01 by comparing the 32 featured games in production (Kindle viewport) with Parchment
(iplayif.com). When a game waits for one key (`CharInput`), the reader shows a single "Continue ›" button, and it
always sends `return` (`src/screens/reader/GameReader.tsx`, `sendChar('return')`). A physical keyboard works
(`glkKey`), but the Kindle has none. Without one:

- **Repeat the Ending** (`eueqjtej7bvnfp5a`, Glulx) opens on "Choose option 1 or 2.". "Continue" does nothing, so
  **the game never starts**.
- **Blue Lacuna** (`ez2mcyx4zi98qlkh`, Glulx) opens on "Press N to begin from the beginning, R to restore an existing
  story, or C to show the Table of Contents." The same screen comes back on every tap, so **the game never starts**.
- **Bronze** (`9p8kh3im2j9h2881`, Z-machine), `HELP`: an Inform menu (N = Next, P = Previous, Q = Quit Menu,
  ENTER = Select). Return always opens the first topic, then the menu again, and so on. **There is no way to reach the
  other topics or to leave the menu**, short of Restart or Load. Every Inform game with a menu-based `HELP` / `ABOUT`
  has the same trap.
- Anchorhead: "Press 'R' to restore; any other key to begin". It starts, but `R` cannot be sent (Menu › Load
  exists).

The menu's legend (N / P / Q) is in the upper window's second and third rows, which the reader does not show
(see [S1.15](S1.15-status-line-rows.md)). Chips found from the status rows work once S1.15 is done. This story must
not wait for it.

## Scope

- **Key chips.** While the game waits for a key, the slot under the text shows, instead of the lone "Continue":
  - **Keys the text names**, found in the last paragraphs since the previous input and in the status rows the
    engine sends (all rows, not only the first). Patterns, at least: `press X`, `press 'X'` / `"X"` / `[X]`,
    `X to <verb>`, `X = <label>` (menu legends), `option 1 or 2`, `1 or 2`, `(1)` / `1.` numbered options, `Y/N`,
    `yes or no`. Each chip shows the key and, when the text gives one, a short label ("N — Next"). The order is
    the order in the text, with duplicates removed and at most 8 chips (the rest goes to the field below).
  - **Always**: "Continue ›" (sends `return`, as now; `Space` for games that ask for the space bar) and
    **"Key…"**, a one-character field that opens the virtual keyboard and sends the first character typed.
  - Letters are sent in lower case unless the game asked for upper case explicitly. Check on Blue Lacuna, Repeat the
    Ending and Bronze (Inform menus accept both), and record what was found.
- A tap on the page keeps meaning "Continue" only when no specific key was found (SPEC §3.6, `[MORE]` / any key).
- Chip labels follow the UI language (`reader.key.*` in `en.json` / `fr.json`). The keys themselves are sent as
  found.
- The hardware keyboard path (`glkKey`) is unchanged.
- SPEC §3.6 updated ("press any key" prompts, single-key prompts).

## Acceptance criteria

- [ ] Repeat the Ending: a "1" chip starts autonomous mode, and a "2" chip starts story mode.
- [ ] Blue Lacuna: an "N" chip starts the game from the beginning.
- [ ] Bronze: `HELP` → the N / P chips move through the topics, Return opens one, and Q leaves the menu back to the
      game (with the legend chips once S1.15 is done; with "Key…" until then).
- [ ] "Key…" sends any letter or digit, on a desktop browser and on the Kindle (virtual keyboard).
- [ ] Simple "press any key" prompts (The Lamp at Saltmere, Cragne Manor, Violet) still need one tap, as before.
- [ ] Checked on the PR preview with the games above, and on the Kindle, or the Notes say why not.

## Notes & decisions

- **Where keys are read** (`src/reader/keys.ts`, `findKeys`): every status row first (they are at the top of the
  screen), then the paragraphs since the last command (at most 12). When the game printed keys after the last key
  sent (a new menu screen), only those are used; when it printed none (Lamp's logbook: "You turn a page (x).") the keys
  since the command stay, so a menu that names its keys once keeps its chips.
- **Patterns:** `press / hit / type / tap / appuyez sur / tapez X` (bare, `'X'`, `"X"`, `[X]`, named keys), `X to …` /
  `X pour …` (a capital letter or a digit, not `A` / `I`), legends `X = label`, alternatives `1 or 2`, `1, 2 or 3`,
  `Y/N`, `yes or no` / `oui ou non`, and numbered options at the start of a line (`1.`, `(1)`, `1)`). "press a key",
  "type a command", "A to Z", "from 1 to 10" give no key. Labels are cut to a few words (≤ 18 characters, not ending on
  an article or a preposition): "N — begin", "C — show the Table".
- **Named keys:** Return / Enter alone is the Continue button; it gets a chip only with a label from a legend
  ("Return — Select"). Space is never a chip: "press SPACE", "space bar", "barre d'espace" make Continue (and a tap on
  the page) send a space. Esc gets a chip. Their names follow the UI language (`reader.key.return`, `.escape`).
- **Lower case:** chips and "Key…" send letters in lower case (shown in capitals). No game seen so far asks for a
  capital explicitly, so there is no exception yet. Inform 6 menus accept both cases.
- **Layout:** the chips take at most two rows above Continue + Key…, in the same slot height as the command bar; a
  chip that does not fit is hidden (its key can still be typed in "Key…").
- **"Key…"** is a one-character text field (it opens the virtual keyboard); the first character typed is sent at once.
  Return in the empty field sends Return (the global key handler ignores text fields).
- **Fixture:** the new prompts are behind two commands of `lamp.z5` (HELP: "Choose 1 or 2.", LOGBOOK: "Press Q to quit
  the menu.", any other key turns a page) instead of after the intro, so the other e2e walkthroughs are unchanged.
- **Real games:** the dev container cannot reach the IF Archive, so Blue Lacuna, Repeat the Ending, Bronze and the
  "press any key" games are to be checked on the PR preview and on the Kindle.
